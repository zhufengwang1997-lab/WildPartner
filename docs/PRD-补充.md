# PRD 补充 v1.6（2026-11-22，优先级高于 PRD 正文中冲突的部分）

## 1. 画面目标：完整地图，但品质优先
用户的标杆是《小王子：星辰之旅》那一类观感：**物件由 Tripo 生成、摆放用心、光照安静柔和**。当前"3.2 万个脚本生成的低多边形色块 + 浓雾"的画面不合格，问题在素材和光照，不在地图大小。

- **地图保持完整**：`docs/reference/world_map.webp` 上的所有区域都要有、都能走到（中央草甸与石阵、河流瀑布与木桥、大湖岸与湖心岛视野、秋色林、深绿林与瞭望塔、悬崖木屋）。可游玩范围约 **600 m × 600 m**（跑步横穿约两分钟；比这更大只会增加空跑路程）。雪山仍为远景。
- **所有看得清的物件都用用户的 Tripo 模型**（清单见 `docs/模型制作清单.md`）：树林也用 Tripo 的树模型经减面、做 LOD 后大量实例化，**不要再用脚本生成"成品"模型**。脚本生成只允许用于：草、花、蘑菇面片，远景轮廓，地形。模型到位前用占位几何体。
- **品质分两层**：
  - 重点区（木屋、石阵、木桥、瀑布、湖岸、瞭望塔，以及连接它们的小路两侧各约 15 m）：按第 2 条手工构图摆放，这是玩家实际看到的 90%。
  - 填充区（重点区之间的林地和草地）：用同一批 Tripo 模型按规则成片摆放，保证密度、不穿帮即可。
- 路要引导玩家：从木屋出发的小路依次串起各重点区，沿路能看到下一个地标。
- 说明书 FR-G01 的"约 1 km²"调整为实际面积，记入 DECISIONS.md 和 STATUS.md。

## 2. 手工感的摆放
不要纯随机撒点。每个区域按"构图"摆：小路两侧成组的树和灌木、岩石旁配花和蘑菇、木屋周围有围栏路灯柴堆。每摆完一个区域，从玩家视角截图自查，和 `docs/reference/style.jpg` 对比。

## 3. 光照与后处理（对观感贡献最大，优先做）
暖色主光 + 蓝紫阴影；柔和的渐变天空；淡蓝色远景雾（当前雾过浓，必须大幅降低）；轻微 Bloom、调色、暗角；树荫斑驳。昼夜循环保留，但把"下午四五点的暖光"作为默认开场时间。

## 4. Tripo 模型的处理
Tripo 模型面数很高。进 Unity 前用 Blender 处理：减面（保持轮廓）、**保留原贴图**、做 2–3 级 LOD、原点和尺寸统一。材质用项目的 Toon Shader 读取原贴图，确保和场景光照统一。

## 5. 骨骼与动作：全部通过 Blender 完成（用户明确要求）
**不要用 Tripo 的绑定和动画功能**（网页或 API 都不用）：用户实测过，做不了本游戏需要的复杂动作。用 Blender（命令行或 MCP，哪个稳用哪个）。

对象和动作清单、优先级见 `docs/玩法设计.md` 的"需要的动作"一节。

做法：
1. 为每个角色建立骨架（人形：骨盆、脊柱 2 节、颈、头、双臂各 3 节、双腿各 3 节；四足：脊柱 3 节、颈、头、四腿各 3 节、尾 2–3 节、耳朵可选；蝴蝶：身体 + 双翅；鱼：脊柱 3–4 节 + 尾）。按网格实际形状对齐关节，对齐后正面、侧面渲染截图自查。
2. 蒙皮：先试自动权重；失败（Tripo 网格常不封闭）时，先做封闭的简化代理网格算权重再传回原网格，或按距离分配权重后平滑。
3. 动作：用脚本打关键帧。循环动作首尾无缝；非循环动作（坐下舔爪子、躺下翻肚皮、蹭）做成"进入 → 循环 → 退出"三段。风格化、幅度克制、节奏有快慢变化，避免机械的匀速摆动。
4. 验证：每个动作渲染 6 帧关键姿势拼图，检查撕裂、穿插、扭曲。每完成一个角色的一档动作，把拼图保存到 `docs/screenshots/anim/` 并在汇报里附上，**不用等用户回复，继续下一档**；用户有意见会事后提。
5. 导出 FBX（含骨骼和全部动作）→ Unity 建 Animator（移动按速度混合；猫的待机行为按停留时间和与玩家距离触发）→ 替换 Prefab 的 Visual。
6. 每个角色每档动作时间盒 45 分钟。超时就把当前最好的版本接进游戏、如实告诉用户差在哪，继续下一个；不要停在一个动作上反复磨。
7. 模型还没到位的角色（如猫）先用占位体把行为逻辑和状态机做好，模型到了再绑。

## 6. 执行顺序
见 `docs/最终指令.md`（唯一的执行顺序依据）。
