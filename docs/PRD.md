## 4. 阶段 1：完整可玩的游戏闭环

### 4.1 美术方向
- 以 `docs/reference/style.jpg` 为风格基准，`docs/reference/world_map.webp` 为地图布局基准。**开工前先亲自读这两张图**，下面的文字是对它们的归纳，以图为准。
- 两张图若不存在，提醒用户（M3）；在等待期间按下面的文字描述先做。
- 所有 Shader / 材质统一成少数几个，为阶段 4 的 GRD 做准备（对应说明书 FR-RD-04）。

**风格要点（来自 style.jpg）**：风格化手绘感的卡通渲染，不是写实。
- 树冠和灌木是成团的、能看出一片片叶子形状的块面，明暗分成 2–3 个色阶
- 暖色阳光 + 偏蓝紫的阴影，树荫在草地上投下斑驳光影
- 草地是高饱和的黄绿色，点缀白色和橙色小花、红蘑菇
- 土黄色小路蜿蜒穿过；白桦和粗壮深色树干的阔叶树混搭
- 远处有偏蓝的空气雾，天空偏淡粉
- 实现手段建议：一个自定义的卡通光照 Shader（色阶化明暗 + 可调阴影色）、渐变雾、轻微 Bloom 和调色。**这是 3 天内可以接近的方向，不要求达到参考图的精细度**；把时间优先花在光照、雾和调色上，这三样对观感贡献最大。

**地图分区（来自 world_map.webp，上北下南）**：
| 区域 | 位置 | 内容 | 对应地貌 |
|---|---|---|---|
| 中央草甸 | 中部 | 开阔草地、土路网、**石阵遗迹**（环形立石） | 草原 |
| 河流 | 西北 → 中部 → 东南 | 从西北高处经多级**瀑布**流下，蜿蜒穿过中部；有一座**木桥** | 河谷 |
| 大湖 | 东北 | 湖中有几座小岛 | 河谷 |
| 秋色林 | 北部、湖岸 | 橙黄色树林 | 疏林 |
| 深绿林 | 西部、南部 | 深绿针叶和阔叶混合林，西侧有一座**瞭望塔** | 疏林 |
| 悬崖木屋 | 东南高地 | 悬崖上的**木屋**，带围栏、路灯、旗帜。**作为玩家起点和结局地点（代替原定的营地）** | — |
| 雪山 | 东北远处 | **仅作远景，不可到达**（用远景网格或天空盒） | — |
| 边界 | 四周 | 岩石悬崖 + 低空云雾自然封边，不用空气墙外露 | — |

五种生物分散在不同区域（草甸、秋色林、深绿林、河边、湖边或夜间），让玩家把地图走一遍。地标（石阵、瞭望塔、木桥、瀑布）用作图鉴线索里的方位提示。

### 4.2 模型流程（占位 → 替换）
1. 盘点 `Assets/_Game/Models/_Inbox/` 里用户已做好的模型，检查每个：面数、贴图、是否有骨骼、有哪些动画、尺寸比例。
2. 生成 `docs/缺失模型清单.md` 交给用户，每项写明：名称、用途、建议的 Tripo 提示词、是否需要绑骨骼、需要的动画（待机 / 走 / 跑）、导出格式（FBX 或 GLB）。同时列出已有模型存在的问题。
3. **缺的全部用几何体占位**（胶囊体、方块、球），占位物用醒目的统一材质，便于一眼看出还没替换。
4. **替换必须零代码改动**：每个生物/道具是一个 Prefab，逻辑挂在根节点，模型是名为 `Visual` 的子节点。用户放入新模型后，你只替换 `Visual` 并重新指定动画控制器。
5. 需要修模型时（缩放、朝向、原点、减面、合并材质）通过 Blender MCP 处理；Blender MCP 未安装则先安装配置。
6. 四足动物若 Tripo 无法绑骨骼：退路是用程序化动画（上下弹跳 + 身体摆动的脚本）让它动起来，并在清单里标注。

完整模型需求（以此核对缺失）：
| 类别 | 内容 | 数量 |
|---|---|---|
| 玩家 | 人形角色，待机/走/跑 | 1 |
| 生物 | 5 种，各有待机/走/跑；**至少 1 种带毛发或羽毛**（说明书 FR-G03） | 5 |
| 树 | 含 LOD，远景用面片 | 2–3 |
| 灌木、岩石 | | 各 2 |
| 草 | 用简单面片网格，不用 Tripo | 1–2 |
| 树 | 另需：白桦 1 种、秋色（橙黄）树 1 种，可由同一模型换材质得到 | — |
| 花、蘑菇 | 小型点缀物 | 各 1–2 |
| 木屋 | 悬崖木屋 + 围栏 + 篝火（起点兼结局地点） | 1 组 |
| 地标 | 石阵立石、瞭望塔、木桥 | 各 1 |

生物的具体种类由 `_Inbox` 里已有模型和参考图决定；都没有时默认：狐狸、鹿、野兔、鸟（带羽毛）、野猪。

### 4.3 世界（说明书 FR-G01、G02、G05）
- Unity Terrain，约 1 km²，三种地貌：草原、疏林、河谷。用编辑器脚本按固定随机种子生成（可重复），布局参照世界地图参考图。
- 植被用 MeshRenderer + LOD Group（**不用 Terrain 自带的草和树系统**，否则阶段 4 的 GRD 接不上），用脚本按规则批量摆放。
- 河谷里有水面（简单的透明水 Shader 即可）。
- 昼夜循环：一天 = 现实 8 分钟，太阳方向、颜色、天空、雾随时间变化。
- 天气：晴 / 雨随机切换，雨用粒子系统。
- NavMesh 烘焙覆盖可行走区域。

## 5. 阶段 2：统一超分中间件（com.zfw.upscaling）

> 白话解释：超分 = 先用低分辨率渲染画面，再放大成高分辨率，用更少的计算换接近的画质。本阶段做的是一个"统一插座"，让游戏不关心背后用的是哪家的超分技术。

### 5.1 第一步：调查（时间盒 45 分钟，产出 `docs/调查-URP超分能力.md`）
读本机 URP 源码，回答：
1. 当前 URP 版本内置哪些放大方式（双线性、FSR1、STP 等）？各自在 Metal 和 DX12 上是否可用？
2. URP / SRP Core 是否已经提供了自定义超分的扩展接口或同名的 `IUpscaler` 类型？如果有，我们的接口如何与之共存（必须放在自己的命名空间 `Zfw.Upscaling` 下）？
3. 在 Render Graph 里，自定义 Pass 插在"后处理前"还是"后处理后、UI 前"更可行？（说明书 2.1 的方案 B 是保底：后处理按渲染分辨率执行，超分在后处理之后、UI 之前。）
4. 相机抖动（Jitter）和运动向量在 URP 里怎么开启、怎么拿到？

根据调查结果确定实现方式，写进 `docs/DECISIONS.md`。

### 5.2 接口（说明书 FR-UP-01，保持签名一致）
实现 `IUpscaler`、`UpscalerQuality`、`UpscalerInputs`，以及四条需求条款：
- `Initialize` 返回的渲染分辨率是所有低分辨率 RT 尺寸的唯一来源
- 显示分辨率或档位变化时重新 `Initialize` 并重置历史帧
- `RecordPass` 只在 Render Graph 里声明资源读写，不改全局状态
- `GetMipBias()` 默认 `log2(渲染宽度 / 显示宽度) - 1`

如果调查发现某条签名与本机 API 无法对接，允许做最小改动，并在 `DECISIONS.md` 里写明改了什么、为什么。

#### 5.3.1 DLSS 的实现路线（代码只能在 Mac 上写，这是本项最大的风险）
按顺序尝试，前一条走通就不用后一条：
1. **调查本机 URP 是否已内置 DLSS 支持**（在 5.1 的调查里一并回答）。如果内置，`DlssUpscaler` 封装 URP 的内置开关即可，这是最稳的路线。
2. 如果没有内置：在 Mac 编辑器里把构建目标切到 Windows，确认 `UnityEngine.NVIDIA` 命名空间能否解析、能否编译通过。能编译就按说明书 FR-UP-03 实现（`#if UNITY_STANDALONE_WIN` + 程序集定义的平台限制，满足约束 C4）。
3. 如果在 Mac 上根本编译不了 NVIDIA 模块：退路是保留骨架，状态标"仅设计"，在 `DECISIONS.md` 写明原因。**不要为此耗时超过 90 分钟。**

无论哪条路线：DLSS 代码在 Mac 上无法运行，只能在 5060 Ti 上第一次见真章。所以必须 (a) 在 23 日的冒烟测试包里就带上 DLSS，尽早暴露问题；(b) 加详细日志（模块是否可用、`IsFeatureAvailable` 结果、Feature 创建成败、每次重建），让用户拷回来的日志足够你远程排错；(c) DLSS 初始化失败时自动退回下一个后端，不能崩溃。

### 5.4 输入准备（说明书 FR-UP-02，IN-01 ~ IN-08）
逐条实现并自测。对当前可用后端不起作用的条目（例如某后端不读 Reactive Mask），仍要把输入准备好并能在调试叠加层里可视化，文档里写明"已生成、当前后端未消费"。
- IN-01 关闭 URP 自带 TAA/FXAA，避免重复抗锯齿
- IN-02 深度与 Reversed-Z
- IN-03 运动向量（含蒙皮网格、植被风动）
- IN-04 Halton(2,3) 抖动，相位数 = 8 × (显示宽度 / 渲染宽度)² 取整
- IN-05 曝光
- IN-06 Reactive Mask：雨滴等无运动向量的透明物体写入遮罩
- IN-07 UI 在超分之后按全分辨率绘制
- IN-08 镜头切换、传送、分辨率或档位变化时 `ResetHistory()`

### 5.5 选择器、GpuCaps 扩展、设置、调试层
- 选择器（FR-UP-04）：按 DLSS → MetalFX → FSR → RenderScale 顺序返回第一个支持的后端（StpUpscaler 的位置自行决定并记录理由）；档位映射 Low→Performance、Medium→Balanced、High/Ultra→Quality；玩家手动选择优先并存盘；启动参数 `-upscaler=`、`-quality=` 可覆盖；结果写日志。
- GpuCaps 扩展（FR-UP-05）：`features` 增加 `dlss`、`fsr`、`metalfx`，schema 升为 2。在 MineEmbers 仓库里改并打新标签，WildPartner 更新引用。
- 设置菜单（FR-G06）：超分方案、超分档位、画质档位、GRD 开关（阶段 4 接通）、调试叠加层开关。切换立即生效。
- 调试叠加层（FR-UP-06）：F3 切换；显示当前后端和档位、渲染 / 显示分辨率、帧率、超分 Pass 耗时；可切换运动向量可视化、Reactive Mask 可视化。
- 约束 C3：游戏层程序集不得引用任何厂商 SDK 程序集。用程序集定义文件强制，并加一个 EditMode 测试检查引用关系。

## 7. 阶段 4：大世界渲染、Windows 验证、收尾

### 7.1 GRD（说明书 FR-RD-01 ~ 06）
> 白话解释：GRD（GPU Resident Drawer）让显卡自己批量画大量相同的物体，减少 CPU 一个个下指令的开销。"Draw Call" 就是这种指令的次数。

- 按 FR-RD-01~04 开启并适配；`-grd=on|off`、`-occlusion=on|off` 启动参数和设置菜单开关接通。
- FR-RD-05：写出不走 GRD 的物体清单及处理方式。
- FR-RD-06：用 ProfilerRecorder 采集 Draw Calls、Batches、SetPass Calls、主线程和渲染线程耗时；同一路线 GRD 开/关各跑一次；记录场景加载时间增量。结果写入 `docs/GRD评估报告.md`，给出 NFR-03 的实测结论。
- 退路：GRD 在本机开不起来或出现渲染错误，记录原因，保留开关为关闭，报告写"未达成"。

### 7.2 Windows 测试机验证（RTX 5060 Ti + GTX 1070 Ti，两台都测）
**原则：Mac 打包，Windows 只运行，零安装。**

准备工作（阶段 0 期间就做）：
- 给本机 Unity 6000.3.28f1 加装 **Windows Build Support (Mono)** 模块（Mac 上不能用 IL2CPP 打 Windows 包，Windows 包用 Mono 后端）。
- 写一个构建脚本，一条命令打出 Windows 64 位包，图形 API 为 DX12。

测试包内容（`WildPartner-win-test-<日期>.zip`）：
- 游戏本体
- `01_冒烟测试.bat`：启动游戏跑 2 分钟自动退出，输出能力报告 JSON 和日志
- `02_完整测试.bat`：自动依次跑"所有可用后端 × 所有档位 + 原生基线"的 PerfRunner 路线、SC-01~06 截图、参考图、GRD 开/关对比，全程无人值守，跑完自动退出
- `03_挂机30分钟.bat`：TC-10
- 所有输出写进包内同一个 `results/` 文件夹（含日志、CSV、JSON、截图、设备信息），文件夹名带设备型号和时间
- `使用说明.txt`：给用户看的三步说明（解压 → 双击哪个 → 把哪个文件夹拷回来）

交付方式：**全程 U 盘，测试机按不联网设计**（测试包运行时不得依赖网络）。打包完成后把 zip 放到 `~/dev/WildPartner-win-builds/`（不进 Git），告诉用户文件在哪、拷到 U 盘的步骤；U 盘建议 exFAT 格式（Mac 和 Windows 都能读写，支持大文件），若用户的 U 盘不是，告诉用户怎么确认和处理。两台测试机用同一个包，`results/` 下按设备自动分文件夹，互不覆盖。结果拷回 Mac 后放进 `bench_results/win-<显卡>-<日期>/`，由你在 Mac 上跑 `quality_eval.py`、`bench_report.py`，生成 `docs/超分评估报告-win-<显卡>.md`。

两轮测试：
1. **23 日冒烟测试（5060 Ti 到手就做）**：用当时能打出来的任何版本，哪怕游戏还是占位几何体。目的是尽早发现"Windows 上起不来 / DX12 报错 / DLSS 模块不可用"这类问题。拿回日志后立即排查。
2. **24 日完整测试**：TC-01（5060 Ti 应选中 DLSS，1070 Ti 应选中 FSR）、完整 bench、TC-10。

注意：
- Windows 原生插件（如 GpuCaps.dll）在 Mac 上编译不了。没有 DLL 时 GpuCaps 会退回用 SystemInfo 采集，测试照常进行，报告里注明。P2：用 GitHub Actions 的 Windows 环境在云端编译出 DLL（代码仍在 Mac 上写），有余力再做。
- 每轮测试都可能只有一次机会，脚本要足够健壮：某一项失败要记日志并继续跑下一项，不能整体中断。
