# 技术决策记录

每条：决定 → 理由。按时间追加。

## 2026-11-22 阶段 0
- **Unity 版本用 6000.3.28f1（Unity 6.3 LTS）**：本机已安装，用户确认不再装 6000.0.x。
- **TierSettings 扩展机制用 `[SerializeReference] List<TierExtension>`**，而不是让游戏继承 TierSettings：多个游戏/模块可以各挂自己的扩展，且已有资产不需要换脚本类型。MineEmbers 的 heatHaze / lakeReflection 移到 `MineTierExtension`。结果：MineEmbers EditMode 21/21（原 20 + 新增 1）、Python 13/13 通过，打标签 `v0.2.0`。
- **三个包用 Git URL + `#v0.2.0` 固定版本**，manifest 中三个都显式写出。MineEmbers 目前是**私有仓库**：本机通过 `gh auth setup-git` 让 Unity 的 git 能拉取。若面试官要从零克隆运行，需要把 MineEmbers 也设为公开（公开前向用户确认，见 PRD 7.3）。
- **项目用 URP 3D 模板（Forward+）创建**，配置写在 `Assets/_Game/Editor/ProjectSetup.cs`（配置即代码，可重复执行）。Windows 只开 D3D12（PRD 要求 DX12），Mac 只开 Metal。脚本后端 Mono（Mac 上交叉编译 Windows 包只能用 Mono）。
- **MSAA 全档位关闭**：抗锯齿交给阶段 2 的超分/时间性方案（IN-01），避免重复抗锯齿。

## 2026-11-22 美术与模型
- **用户已有的 Tripo 模型（女巫、月影兔、月影蝶、白色神鹿）都没有骨骼和动画** → 采用 PRD 4.2 第 6 条退路：程序化动画（弹跳、摆动、扇翅）。
- **GLB 不直接进 Unity**：Unity 不原生支持 GLB，引入 glTFast 会多一个依赖。改为 `tools/blender/process_glb.py` 在 Blender 无界面模式下批处理：合并网格 → 减面 → 统一尺寸 → 原点放到底部中心 → 导出 FBX + 基础色贴图 PNG。可重复执行。
- **木屋室内家具（门、窗、桌、凳、床、壁炉、壁灯）原始面数约 190 万/个、56MB/个**，减到 0.8–1.5 万面。原始 GLB（共约 400MB）不进仓库，只放在用户桌面 `素材/`；四个角色/生物的原始 GLB（共约 14MB）放进 `Assets/_Game/Models/_Inbox/` 走 LFS。
- **缺失的模型（树、灌木、岩石、木屋外观、石阵、瞭望塔、木桥、两种生物等）由 Blender 脚本程序化生成**，而不是请用户在 Tripo 补做：用户要求“能自己做的全部自己做”，且程序化生成可重复、风格统一、面数可控。
- **卡通光照用一个自写 HLSL Shader（`WildPartner/Toon`）**：色阶化明暗 + 蓝紫阴影色 + 边缘光 + 可选风动。所有不透明物体共用它（FR-RD-04），参数全部放在 `UnityPerMaterial`，兼容 SRP Batcher 与 GPU Resident Drawer；带 DOTS instancing。
- **风动运动向量**：MotionVectors Pass 用上一帧的时间（`_WP_WindTimePrev`）和上一帧的物体矩阵各算一次风动位移，二者之差就是真实屏幕运动（FR-G07 / IN-03）。

## 2026-11-22 世界与流程
- **整个场景由 `WorldBuilder.Build` 一次生成**（地形高度、4 层地表、水面、地标、植被摆放表、灯光、后处理、相机、系统对象、NavMesh），固定种子 20261122，可重复。场景文件只是生成结果。
- **植被是摆放表（位置/朝向/缩放）+ 运行时实例化 Prefab**（MeshRenderer + LOD Group），不用 Terrain 自带树草（PRD 4.3，便于阶段 4 GRD）。共约 3.2 万个实例。
- **NavMesh 用物理碰撞体烘焙**：烘焙前临时生成植被，让树干、岩石成为障碍；烘焙后清除。
- **Blender 导出的 FBX 单网格节点带 90° X 旋转**，摆放时设置根节点旋转会把它覆盖（桥侧翻、角色趴下）。在导入规则里把节点旋转烘焙进顶点并清零，所有模型统一处理。
- **地形贴图 UV 用 Terrain 自带的 uv × `_SplatN_ST`**（Unity 传入的是"整块地形重复次数"，不是世界坐标缩放）。
- **草叶法线统一朝上**（`_UpNormal`），避免竖直面片在侧光下发黑，与地面颜色衔接。
- **运行时冒烟测试 `-smoketest`**：在打包好的游戏里通过与 UI/按键相同的入口自动跑完整循环，输出截图和逐步 PASS/FAIL；只读测试钩子 `GameInput.SimCapture/SimSneak` 仅在该参数下使用。

## 2026-11-22 · 新玩法 v1.5 第一批
- **女巫骨骼与动作全部由 Blender 完成**（`tools/blender/rig_humanoid.py`，17 根变形骨骼）。Tripo 网格是数千个开放碎片，Blender 自动热量权重不可用，改为自写权重：按到骨骼距离取前 3 根；手臂按"碎片整体是否在手臂胶囊内"判定；腿严格按左右和高度；裙摆在髋/大腿之间混合，中线碎片留在髋。源文件存 `Art/Rigged/`（不放进 Assets，避免 Unity 导入 .blend）。
- 动画控制器：一维混合树，参数 Speed；走/跑的阈值 = 该动作在 Blender 里实测的落地脚后滑速度（`Rigged/<名字>_speeds.json`，女巫：走 0.95、跑 3.2 m/s），保证脚不打滑；超过跑的阈值时按比例加快播放。
- **动作改为"动捕式"曲线（用户反馈动作僵硬，参考 Mixamo）**：髋/膝/踝按真人步态曲线（周期样条，可无缝循环）；骨盆高度逐帧求解让支撑脚贴地（上下起伏由腿自然产生）；骨盆转动和侧倾、胸部反向扭转、头部保持平视；手臂跟随延迟、前臂再延迟；待机为重心落在一条腿上的放松站姿，带呼吸和环顾。修正了手臂下收方向写反导致手臂一直张开的问题。
- **移动速度改为接近真人**：潜行 1.0、走 1.6、跑 4.0 m/s（原 1.6 / 3.0 / 5.5 和动画步幅差太多，会明显滑步）。600 m 地图跑步横穿约 150 秒。
- **林鸮移除，猫作为默认宠物**：`CreatureDef.startsWithPlayer`，新游戏时直接成为伙伴，计入 1/5。木屋室内出生点做好后再把猫放进屋内。
- **光照**：默认开场 16:30；16–17 时主光更暖；环境光的地面色偏蓝紫；雾大幅变淡（晴天 140–1100 m，雨天 40–380 m）；后处理加分离色调（暗部蓝紫、亮部暖橙）和轻微暖白平衡。
- **Tripo API 暂不可用**（API 账户余额为 0，充值失败），改由用户在 Tripo 网页上手动做模型，清单 24 个（新增柴堆、图鉴书，篝火可不做）。
- **跳跃（空格 / 手柄 A）**：起跳高度 0.9 m（重力 −20，滞空约 0.6 s），离地后 0.12 s 内仍可起跳、落地前 0.12 s 内按下会在落地时起跳，空中保持水平速度。动画分三段：起跳（蹬地伸展→收腿）、空中（循环）、落地缓冲；从边缘走下去会直接进入空中动作，小台阶（离地 < 0.25 s）不切换动作。跑动中落地会立即接回跑步。
- **头发与裙摆跟随摆动（用户要求）**：在 Blender 加次级骨骼——头发左右各 3 节（挂在头上），裙摆前/后/左/右 4 片（挂在髋上）；头发按"后脑以下、背后的碎片"整块识别，裙摆在原髋/大腿权重中按方位分出一部分给 4 片。摆动是关键帧里的跟随动作（越靠下越滞后），不是实时物理：待机轻微、走路小幅、跑步头发向后飘约 25°且随步伐起伏、空中头发裙摆上扬、落地先压下再回弹。共 27 根骨骼。
- 走路步幅加大（髋 +33/−19°），动画自然速度 1.08 m/s。
- 起跳加 0.1 s 下蹲蓄力（`Witch_speeds.json` 的 JumpLaunch，游戏里同步推迟离地）；落地下蹲更深。

## 2026-11-22 画面整改 1–5
- 地图从 1024 m 缩到 600 m（PRD-补充），设计坐标统一乘 `WorldLayout.K`，避免大片空旷。
- 草地用 GPU 实例化（`Graphics.RenderMeshPrimitives`）而非 Unity 地形草：可控草叶形状、风、主角推草、运动矢量（为超分做准备）；密度/高度/枯黄由烘焙贴图驱动，与地形着色器共用地面色块图。
- 雾改为自写高度雾全屏 Pass（指数高度积分），关闭 Unity 线性雾：线性雾只看距离，会把整个画面洗灰。
- 远山不用模型，用 4 层环形山脊网格 + 专用着色器，画在天空之后且不写深度：高度雾把它当天空，只在地平线处加雾，层次靠每层自己的淡化参数控制，便宜且稳定。
- 云放在天空着色器里（2D 噪声投影），不用面片：零额外 draw call，不会穿帮成"六边形块"。
- 分离色调高光从橙色降到浅暖色：原设置把蓝天中和成了灰紫色。

## 2026-11-22 画面整改 8（猫动作）
- 猫骨骼自己在 Blender 用脚本搭（`tools/blender/rig_cat.py`），不用 Tripo 绑定（用户要求），也不用 Blender 自动权重：毛茸茸的低模上热扩散权重会把腿和肚子粘成一片，按身体区域（脊柱距离、腿部半径、尾巴区域）手写权重更干净。
- 动作在 Blender 里手 K 后导出 FBX，同时导出每段动作的地速（`Cat_speeds.json`），Unity 混合树阈值直接用这个值，播放速度 = 实际速度/动作地速，避免滑步。
- 三个闲置动作由主角状态触发而非随机：停下 2.5 s 坐下舔爪、20 s 躺下翻肚皮、主角走近时蹭腿——玩家停下来看猫时一定能看到，最容易被注意到。
- 冒烟测试必须在显示器亮着时跑：显示器睡眠时 Metal 拿不到画面缓冲，游戏会卡住。夜里无人值守时用 `caffeinate -dimsu` 包住 `tools/smoke.sh`。
- 白鹿的脖子较短，低头吃草时鼻子只能到腿中部（再低脖子根会折）。游戏里草高 15–35 cm，鼻子埋在草里看着自然，不再强求贴地。
- 动物的走/跑混合：速度在走路动作地速 1.5 倍以内时只加快走路播放，不混入跑步（否则 1.4 m/s 漫步的鹿会混进一点奔跑，腿乱）；超过才过渡到跑，跑速以上再加快播放（上限 2.6 倍）。
- 兔子、蝴蝶、锦鲤的"走/跑"不是脚踩地的动作，地速用设计值写进 speeds.json（兔：跳距÷跳一次的时间）；兔子小跳和大跳的起跳/落地在同一相位，混合树按速度在两者之间过渡不会错拍。
- 锦鲤原模型斜躺，用主轴分析（PCA）找身体长轴、较"厚"的一端当头，统一转成朝 -Y。
- 猫带路只在猫离主角 12 m 内、目标在 8–50 m 之间时触发，冷却 40 秒：太频繁会变成"自动导航"，失去找宠物的乐趣；带路时猫停下的位置朝目标方向只走 4.5 m，只指方向不带到跟前。
- 冒烟测试必须在显示器亮着时跑（见上）；新增的带路检查用模拟输入 `GameInput.SimMove` 走两步来触发。
- 树种不够时用"重新着色"补：只改叶子色相（色相 45°–175° 的像素），树干和枝条的棕色不受影响。这样同一个 Tripo 阔叶模型能出三种树（原色、深蓝绿、圆冠秋色），既不花 Tripo 点数，又替代掉了长得像针叶树的秋色树。
- 截图机位周围留空地（WorldBuilder.ViewClearings），而不是在截图时临时隐藏树：游戏里玩家走到同一个地方，看到的画面和截图一模一样，没有作假。
- 近镜头网点渐隐用屏幕空间 4×4 Bayer 抖动 + clip，不改用半透明：保持不透明渲染队列，不破坏深度、阴影、运动矢量，也省去排序问题；阴影通道不做渐隐（光源相机是正交的，w=1）。
- 天空渐变不在线性空间直接混合：暖色地平线和蓝色天顶在线性空间混合时，中间大半个天空都会变成灰紫色。改为先开方再混合、再平方（近似感知空间），并用 1-(1-up)^3.2 的曲线让颜色更快到达天顶蓝。
- 陡坡岩石在地形着色器里按法线 y 值混合（0.74→0.50），不另外刷控制贴图：重建世界、改地形时不用维护第二份贴图，所有陡坡自动一致。
- 地图缩小（试玩反馈 4）只改 `WorldLayout.Size`，地标坐标继续用参考地图像素 × K 表示，不逐个手改。原来以米为单位调好的距离，统一乘 `WorldLayout.F = Size/600`。木屋平台半径、坡道、河宽、截图特写距离这类"结构尺寸"保持原米数，因为模型没有缩小。
- 被捕捉中的动物（还没察觉主角时）原地停下、朝向主角，不再继续闲逛。原因：捕捉时主角站着不动，兔子以 1.8 m/s 闲逛 2 秒就走出 3.6 m 的捕捉范围，玩家会觉得"按住了却抓不到"。地图缩小后，冒烟测试的兔子出没点正好暴露了这个问题。
- 地图（试玩反馈 3）的底图在编辑器里预先烘焙成一张俯视贴图（`MapBaker`，世界重建时自动重烘），运行时小地图和大地图都只是 UI 上贴这张图，不用相机实时渲染。原因：实时小地图相机等于每帧多渲染一次场景，影响帧率，也会干扰后面超分的性能测试数据。代价是地图改动后必须重烘（已接在 `WorldBuilder.Build` 末尾）。
- 烘焙时关掉雾、云、远山和"近镜头网点渐隐"：正交相机的 clip.w 恒为 1，渐隐会把所有树冠抖掉；同时把 LOD 偏移临时调大，防止俯视远距离时树被 LOD 剔除。
- 风格化在 C# 里逐像素做（色阶分层、向羊皮纸色偏、亮度模糊后的 Sobel 墨线、纸纹、焦边），不另做着色器：只在编辑器跑一次，简单可控。注意 Unity 的 `Mathf.SmoothStep(a,b,t)` 是在 a、b 之间插值，不是 HLSL 的阈值函数，要自己写。
- 小地图跟随镜头旋转（镜头朝向=上方），超出范围的地标钉在圆边上；未收集的宠物不显示，避免变成"自动寻宠"。大地图固定北朝上，打开时暂停（新增 `FlowState.Map`），按 M 或 Esc 关闭。
- 草（试玩反馈 5）仍是 GPU 实例化 + 顶点着色器里按格子哈希摆放，但改成细草叶：每丛最多 24 片（16 片从约 5 cm 的根部向外弯，8 片散在格子里），每片 4 节 + 尖、宽 1.4–3 cm、高 30–62 cm，向一侧弯、尖端下垂。
- 草的 LOD 不换网格形状，而是"前缀子集"：三档网格分别是同一丛的前 24 / 10 / 4 片，着色器按距离从后往前把草叶缩没、同时把剩下的加宽。区块切换到更小网格时，被丢掉的草叶早已是零尺寸，所以没有接缝。细草在远处会小于 1 像素而闪烁，所以宽度至少保持约 1.3 像素。
- 细草挡不住地面，所以地形着色器读同一张草地密度图，在有草的地方把地面改成"草根附近的暗绿"（近处）到"远处草地色"（远处）。缝隙看起来像更多草，远处草叶缩没时颜色和地面一致。平地受光比草叶亮，所以地面故意比草暗一档。
- 动物也会把草推开（最多 6 个，和主角推草同一套）：50 cm 的草里，兔子、猫只露出上半身，不会完全看不见。女巫的腿只遮到小腿。
- 法线：草叶法线（朝可见面翻转）再向上混 60%，配合包裹光照，背光的草叶不会发黑，也不会逐像素翻转闪烁。
- 院子树桩（试玩反馈 1123b-1）不再写死坐标，而是在院子侧边按"离任何小路 ≥ 3.2 m"自动找位置，底部下沉 14 cm 埋进草里，脚下放两丛蘑菇和两丛花。以后路线改动时树桩不会再落到路上。
- 猫舔爪（1123b-2）在 Blender 里用求解器摆姿势：前臂各关节有角度限制，坐标下降法让肉垫贴到嘴前（舔的几帧肉垫到嘴最近约 2 mm），另一只前爪贴地（离地 0.2–9 mm）。为此扩大了前腿的蒙皮范围，并把前腿、胸口、脊椎的权重沿网格边做了平滑，否则抬爪时皮肤会撕成一片暗色扇面。
- "从耳后往前抹脸"没有做成原样：爪子绕到耳后时胸口和肩膀皮肤严重撕裂，超过 45 分钟时间盒。退而求其次：爪子停在脸前，头在爪子上蹭一下（同样是洗脸的动作，但是头动、爪不动）。记为已知问题。
- 猫抬爪时胸口还会露出几个小破洞（看穿到背景）。临时办法：猫的材质改成双面渲染，破洞显示成暗色毛而不是透明。根治需要重做胸口拓扑或重新蒙皮，记为已知问题。
- 木屋室内（1123b-3）是地图外的一个独立房间（`WorldLayout.InteriorOrigin`，地图西边 70 m、低于边缘山脊），进出门时淡出、传送、淡入，而不是把室内做进木屋模型里。原因：Tripo 木屋是一个外壳模型，里面没有可用空间，而且参考图里的房间（8 × 5.5 m）比外壳还大。放在地底下不行：地形碰撞体把地面以下都当实心，角色会被往上推；地图外没有地形和雾，也看不到。
- 室内照明：进门后 `EnvController.Indoors = true`，太阳强度归零、关阴影，环境光换成暖色，关掉高度雾，近镜头网点渐隐距离缩短。光源只用壁炉（闪烁）、三盏壁灯、一盏补光和两扇窗户的"日光"聚光灯（颜色和亮度跟着外面的时间走），都不投影。窗户后面是一块颜色跟天空走的面片。
- 屋外的门：用 Blender 脚本（`tools/blender/cut_cabin_door.py`）把木屋模型 LOD0 上门板的面切下来，变成一个原点在门轴上的独立物体 `Cabin_Door`，游戏里绕门轴向内转 70°；门洞后面放一块深色板，开门时看到的是"屋里的暗处"，不会看穿到天空。门板的开门方向在运行时自动判断（朝屋里转）。
- 修了一个早就存在的问题：`ConfigureLods` 只给木屋、悬崖、瞭望塔配了 2 级 LOD，但模型有 3 个 LOD 网格，第 3 个（LOD2）不在 LOD 组里，所以一直和 LOD0 叠在一起画（多一份三角形，而且木屋门洞会被 LOD2 的关着的门挡住）。现在多出来的 LOD 网格直接关掉渲染。
- 进出门的瞬移走 `PlayerController.Teleport`，它会发出 `CameraCut` 事件，这就是超分阶段要接的 `ResetHistory()` 入口（IN-08）。超分本身还没做，所以"重置历史"这一步目前只到事件为止，接上超分后再验证。
- 新游戏：主角躺在床上（模型绕脚底转成平躺，镜头目标临时降到床面），黑屏淡入，停 1.3 秒后短暂黑一下，站到床边开始游戏。没有专门的起床动画。
- 床：按 E 睡觉，白天睡到 20:30，夜里睡到 7:00，并存档；存档记录"是否在室内"，读档时恢复室内光照。桌上的书按 E 打开图鉴（就是 Tab 的那本）。
- 女巫头发和裙摆（1123b-4）改成运行时的弹簧链（`SecondaryMotion`）：两条 3 节头发、4 片裙片，每个点被弹簧拉向动画姿势，同时受空气阻力（水平强、竖直弱）。跑步向后飘、转身滞后、落地甩一下再弹 2–3 次，都来自同一套物理，不分别写特殊情况。原来烘在动画片段里的头发/裙摆"跟随动作"不再使用（会和弹簧叠加两次，起跳时头发反而先抬起来），这些骨头每帧从绑定姿势开始。
- 空中时头发、裙摆点也受同样的重力，否则她下落时这些点"跟不上"，每次小跳都飘到极限。限制：裙片只能往外不能往腿里，头发不能往前穿进后背；角度上限头发 80°、裙片 50°。
- 已知差距：长距离下落时头发会明显飘起（8 m 落下约 26 cm），但裙摆只飘起 1–4 cm，比需求描述的"向上飘起"弱。用户 11-23 看过效果表示满意，暂不再调。
- 录屏用 `tools/motion_demo.sh`（游戏内固定 30 帧/秒逐帧截图 + 角度数据 motion.csv，PIL 合成 GIF）；机器上没有 ffmpeg，所以是 GIF 不是 MP4。
- 猫站位（1123b-5）：主角停下 0.35 秒后，猫走到她右侧 0.5 m（按她的朝向），转到和她大致同向，然后才开始坐下舔爪等待机动作。右侧被挡（导航网格边缘、墙、树、石头、家具）就去左侧，再不行去身后。她再走时猫回到身后跟随；猫的导航转身速度降到 260°/秒，不会原地瞬间转身。
- 同种多只（1123b-6/7/8）：`CreatureDef.homes` 每个家一只，`WorldBuilder` 按家生成。"收集"只按物种记：抓到一只后同种其余的 `CanBeCaptured` 恒为 false（仍会逃），存档格式不变，读档每种恢复一只伙伴。没有做"同种其余的也变成伙伴"——用户要求其余留在野外。
- 月兔"被打断先警觉"只在读条中警觉值满时触发（新增 Startled 状态，约 1.1 秒）；没在读条时被发现仍按原规则直接逃。兔子没有吃草/竖耳动画，用 LateUpdate 在动画之上转耳朵和头、脊柱；这是程序姿势，幅度有限。
- 鱼群不是 Creature：单独的 `FishSchools`，普通 MeshRenderer + 两个共享材质（SRP Batcher），不做 GPU Instancing 着色器（Toon 着色器已兼容批处理，40 条鱼开销很小）。鱼的网格是代码生成的；尾鳍两面必须用各自的顶点，共用会让法线抵消成零，着色器出 NaN，表现为黑色小鱼外面一大团白色泛光（已修）。鱼群中心自动移到 0.6–1.4 m 深的浅水，湖里原定位置水深 5.8 m。
- 骑鹿：没有骑乘动作，复用女巫待机动作，在其上用程序把大腿前抬、外分，小腿下垂；鹿每帧跟随她的位置和朝向（骑乘时关掉鹿的导航和碰撞体），而不是她跟着鹿。骑乘时不能跳、不能捕捉、不能进屋；暂停/图鉴/地图不下鹿，回主菜单、结局、进屋会下鹿。
- 展示素材用独立录制模式 `-showcase`（`tools/showcase.sh`）：白天晴天、单独的近景相机跟拍目标动物；冒烟测试截图只用来证明功能，常在夜里或雨里，不适合给人看效果。
- 换树（2026-11-23）：用户替换了 4 个树模型，品种都正确，所以撤掉此前的替代方案（秋色树用阔叶树网格重新着色、白桦不种）。变体只保留两种贴图重着色：`Broadleaf_Deep`（深蓝绿阔叶）、`Autumn_Red`（枫树金黄叶改橙红，只改亮且饱和的金色像素，树皮不动）。各区域树种比例见 `WorldBuilder` 的区域表。

## 试玩反馈 1123c（2026-11-23）
- 边界（A1）：离边缘 17 m 硬限制，外侧地形升成 14–22 m 的山崖带，所以看起来是"山太陡"。所有移动方式（走、跑、跳、骑、游、踏水、爬）在每次移动后都经过同一个 `GuardWorld`，不各写一套。掉出地形或卡在空中 3 秒回到最近安全点（每 0.5 秒记一次：着地、干地、不骑乘）。
- 岩石贴地（A2）：按岩石底面 10×10 网格找最低点，压到地形下 5 cm；需要下沉超过石头高度 60% 的（坡太陡）先沿坡往里挪，最多 6 m，还不行就删（删了 116 块）。
- 木门白线（A3）：不是光照问题，是 Tripo 减面后的网格有几千条开放边，裂缝透出后面的亮色。办法：门后加深色背板 + 道具材质改双面。
- 瀑布（A4）：河流着色器按深度淡出，用在陡峭瀑布上近看会消失，所以瀑布改用专门的水帘着色器（固定不透明度、双面、顺流条纹、唇口白水、底部泡沫）。透明部分挂 `WaterfallSurface` 标记，留给超分阶段写 Reactive Mask。
- 白鹿视野（B1）：视锥 + 听觉两套感知，只听见时警觉上升慢（×0.6）。施法时"只听见不转头"——否则听见 → 转头 → 看见 → 逃走，背后潜行永远抓不到。正面施法被看见时警觉至少 0.9/秒（约 1 秒逃走），否则警觉速度追不上 2.6 秒的施法读条，正面也能抓到。
- 宠物轮换（B2）：其余伙伴不销毁、不移出场景，只关渲染和碰撞并停在主角脚下 50 m，切回时就地出现，存档只多一个 `currentPet`。能力全部按 `PetSwitcher.Is(id)` 判断，不另做能力系统。锦鲤踏水用一块跟着脚下走的隐形碰撞板（水面下 0.1 m），角色控制器照常走和跳。
- 游泳（B3）：不用物理浮力，直接把脚底拉到水面下 0.95 m（缓慢起伏），水深 > 1.05 m 进入、< 0.9 m 退出（留回差防抖）。暗流只在游泳时生效，2.8 m/s 大于快游 2.0 m/s。
- 攀爬（B4）：只有名字以 Rock / Cliff / Watchtower 开头的物体和地形可爬，而且墙要高过头顶；动作切换按"头顶被挡 → 离墙最多 0.7 m 绕过 → 找上方能站的平面翻上去"。瞭望塔的窗洞和窗台会让贴墙射线穿空，所以给塔身（平台以下的顶点）做了凸包碰撞体，平台本身仍是原模型。抓墙判断用实际移动方向（相对镜头），不用"按了 W"。
- 动物分布（B5）：位置由编辑器工具 `HabitatPicker`（按地形坡度、水、导航网格自动挑）算出后写死在代码里，可重复。环境动物不用模型，运行时用球体和扇形面片拼，90–110 m 外整组关掉；"任何地方 25 秒步行内有动物"由冒烟按 10 m 网格统计。
- 树（C1）：用户原始模型约 4.8 万面，直接做 LOD0（不减面），后面三级 1.4 万 / 4000 / 1000。马赛克感主要来自每个面片法线各不相同，在卡通色阶下变成一块块，所以树冠顶点法线改为绕树冠椭球的法线（80% 椭球 + 20% 原法线），树干保持原法线。贴图上限从 2048 改为 4096（原图就是 4096）。
  - 帧时间（M5 Max，1600×900，冒烟同一机位，3 秒平均）：森林 2.3 → 3.8 ms，草地 1.7 → 2.4 ms。1070 Ti 上未测。（另一次 5.5 / 7.4 ms 的读数是测试时用户的游戏也在跑，不算。）
- 水面反射（C2）：选"天空渐变 + 一个实时反射探针"，不用 SSR。理由：URP 没有内置 SSR，自己写要额外的全屏 pass，而且水面多在低角度看，屏幕空间反射会丢掉画面外的山和树、边缘闪烁，超分时还会多一个不稳定来源。探针不每帧渲染：开始时、游戏时间每过 15 分钟、天气变化时各渲染一次，每帧一个面（时间切片），128 px。折射需要 URP 的 Opaque Texture，四档画质都打开了（低档 4 倍降采样）。

## 试玩反馈 1123d（2026-11-23）
- 锦鲤钓鱼（1）：不另做物理钓线，浮标、线、鱼的位置每帧按状态直接算（抛出是一条弧线，收线时浮标沿"落点 → 栈台"按进度移动并左右摆）。张力条是一个 0–1 数：按住 E +0.62/秒，松开 −0.55/秒，鱼的挣扎 = 慢摆（正弦）+ 每 0.5–1.1 秒一次随机猛拉，锦鲤力气是普通鱼的 1/0.6 倍。绿区 0.30–0.72 收线最快（约 5 秒收满），黄区一半速度，红区（<0.1 或 >0.9）不进并计时，累计 1.2 秒脱钩。这样"按住/松开"两个动作就够，不需要额外按键。
  - 几率用"保底"而不是纯随机：65% / 80% / 100%，保证第 3 次一定是锦鲤，符合"正常 2–3 次能钓到"。
  - 钓竿是运行时拼的道具（木杆 + 握把 + 竿头发光石），每帧放在右手、沿前臂方向上翘，不绑到骨骼上——Blender 里手骨的朝向在不同动作里不一致，按前臂方向摆更稳。浮标、线、发光石用 URP 粒子的 Unlit 着色器上色（它一定在包里），不用 Shader.Find 找别的着色器，避免打包后丢着色器。
  - 锦鲤被钓起时由钓鱼系统接管位置（Creature.Scripted），落地后走原来的捕捉事件（CaptureSystem.Award），图鉴、存档、宠物轮换都不用改。
  - 栈台位置由编辑器按河岸地形自动选（两岸里离河心更近、岸坡更缓的一侧），锦鲤的家在运行时按栈台的抛竿点重新摆（每处两条），所以改地形后不会错位。
- 水流（2）：根因是水面着色器里法线贴图的采样坐标是 `p + flow × t`，图案因此往上游走；流纹那一项是 `− t`，方向是对的，两者打架。改成统一 `p − flow × t`。流速按河道每个控制点给一个系数（瀑布下 1.7–1.8，往湖口降到 0.12，湖里 0），写进河面网格的第二套 UV；着色器用两相位交替淡入淡出（flow map 的常用做法），避免流速不均时贴图被越拉越长。同一个系数表（WorldLayout.RiverFlow）给漂浮物、鱼群、游泳推力共用，保证看到的和感受到的一致。出湖到池塘那段按地势是从湖流出，没有改成反方向。
- 月影蝶（3）：用"晴朗的夜晚"作为一个新的出现条件（19:30–5:00 且不下雨），月光花的开合、发光、光晕都由同一个判断驱动，蝴蝶和花永远一致。远处可见靠一个按距离渐显的大光晕（10 m 内不显示、40 m 外最亮），比单靠点光源可靠（点光源在远处只照亮一小块地面）。
  - 天气：去掉了"每 3 分钟必下雨"（原来给雨天锦鲤的保底），否则晴夜很快会被强制变成雨夜。保底改放在睡觉上：睡到夜晚 30% 下雨，连续两次雨夜后第三次必定晴，晴夜开头 5 分钟不变天；连续雨夜数存进存档。

## 试玩反馈 1123e（2026-11-23）
- 室内木门发光（1）：根因不在门。门背后有两块代码生成的网格：门板背板（DoorBacking）和拱形填缝（DoorArchInfill）。它们的"双面"写法是同一组顶点配正反两组三角形，`RecalculateNormals` 把正反两面的法线相加，结果为零。着色器对零向量做 normalize 得到 NaN。这些 NaN 像素在门板的裂缝里显示为黑点，又被泛光（Bloom）放大成一大团白光，看起来就像门在发光，还盖住了附近的女巫。1123c 修鱼尾时遇到过同一个坑。
  - 用户列的排查项都核对过，都不是原因：
    - 门的材质：自发光 0，用的是 Toon 着色器，受光照影响。
    - 室内的太阳：已经关掉，强度 0。
    - 反射探针 / 光照探针：Toon 着色器不采样反射探针；环境光在室内被设成暖色。
    - 门的法线方向：门模型的法线检查过，没有零或 NaN。
  - 修法：
    - 正反两面各用一组顶点。
    - 双保险：Toon 着色器的主光照和 DepthNormals 两处 `normalize` 改成 `SafeNormalize`，以后哪里再出现零法线也不会变成 NaN。
    - 冒烟加一项：室内所有可读网格不能有零或 NaN 法线。
  - 顺带修了室内屋顶：两块坡顶的旋转方向反了，屋脊低、屋檐高，前墙上方留出约 1.3 m 的缝能看到天空。
- 锦鲤水瓶（2）：
  - 水瓶是运行时用旋转体网格拼的（玻璃、水、软木塞、挂绳），不新增模型。玻璃和水用粒子 Unlit 着色器的半透明版本，锦鲤本体是不透明的 Toon，所以隔着玻璃能看到。
  - 挂点用女巫的 Hips 骨骼加右侧偏移。摆动是一个弹簧阻尼摆，输入是挂点的加速度，再叠一点走路时的上下颠。
  - 锦鲤在瓶里按比例缩小，约 7.5 cm 长。
  - 水边判断：在她周围 0.6–3 m 的 14 个方向上采样，找"有水且水深 > 0.4 m"的最近点。进入水里的距离阈值是 3 m，回到瓶里的阈值是 4.5 m，留出回差，避免在岸边来回跳。
  - 跃出、跃回、跃出水面都用抛物线插值，不走物理。
  - 踏水的淡红涟漪挂在女巫的脚步事件上，所以和脚步声同步。
- 月影蝶（3）：
  - 发光程度 `Nightness(hour)` 是时间的平滑函数：17:30→19:30 渐亮，5:00→6:30 渐灭；下雨时乘以 (1 − 0.55 × 雨量)。翅膀的自发光（MaterialPropertyBlock）、宠物灯和星尘数量都只看这一个数，三者始终同步。
  - Toon 着色器新增 `_EmissionTint`，默认白色，其他材质不受影响。翅膀发光 = 贴图纹路 × 蓝紫色调，所以是纹路在发光，不是整块变成紫色。
  - 星尘由代码按飞行速度发射：每秒 5 + 9 × 速度 颗，乘以发光程度。
  - Reactive Mask：新建 `ReactiveMaskSources` 统一登记没有运动向量的透明物，登记时就把运动向量设为 ForceNoMotion。已登记：星尘、雨、瀑布。超分阶段的遮罩 Pass 直接读这张表。
- 声音（4）：
  - 没有用 AudioMixer 资源。Unity 不能用代码创建 AudioMixer 资源，而一个手工混音器对这个项目也够用。现在的做法是三个类别系数（音乐 / 音效 / 环境声）乘以各自的基准音量，主音量走 AudioListener.volume，全部存在设置文件里。
  - 层次靠基准音量：音乐 0.34 > 环境声（风 0.11、雨 0.13、瀑布近处 0.42 × 0.9）> 脚步（走 0.14、跑 0.22、潜行 0.035，脚步片段统一响度 RMS 0.045）。
  - 冒烟按"片段有声部分的 RMS × 基准音量"比较各层，并检查音效的 RMS 和峰值都不超过音乐。这只是对片段数据的比较，不等于人耳听感，人耳没有试听过。
  - 脚步声重新处理现有的 CC0 片段：去掉高频和硬起音（咔哒、啪），叠一层很轻的草叶"沙沙"声。没有下载新素材，因为下载需要用户确认。
  - 猫叫和呼噜都是合成的：猫叫基频从 520–760 Hz 降到 330–430 Hz，并做低通；呼噜是约 25 Hz 脉动的低频噪声加两次"呼吸"起伏。

## 超分阶段第一步：抗锯齿（2026-11-23）
- 在原生分辨率下做时间性抗锯齿，可以在"关 / TAA / STP"三种模式之间切换。默认 STP，在设置菜单、F3 调试层（F4 循环切换）、启动参数 `-aa=` 三处都能切换，选择存进设置文件。
  - URP 17（Unity 6.3）里，把管线资源的 `upscalingFilter` 设为 STP 后，即使渲染比例是 100% 也会运行 STP。这时 URP 内部把相机强制设为 TAA 模式，由 STP 取代 TAA（见 `UniversalRenderPipeline.cs` 中 `upscalerSupportsTemporalAntiAliasing` 那段）。所以原生分辨率的 STP 就是"一个更好的 TAA"，之后降分辨率做超分时直接调渲染比例即可。
  - TAA 模式用 URP 自带的时间性抗锯齿（高质量）+ 对比度自适应锐化 0.4。STP 不提供锐化参数。
  - 两种时间性模式都要满足这些前提：相机开启后处理、关 MSAA、关动态分辨率、渲染器支持运动向量。`AntiAliasing.ApplyTo` 每次切换都会强制设好这些。
- 切换画质档位会换一份 URP 资源，所以档位变化后要重新应用抗锯齿设置。
- 所有镜头切换（`PlayerController.CameraCut`：进出木屋、传送）都调用 `ResetHistory()`，这是 IN-08 的第一处接入点。
- 草叶的 mipmap 覆盖率：检查过，项目里没有"镂空贴图 + Alpha Clip"的植被。草是 GPU 生成的几何草叶，树是实心网格，所以不存在"远处 mip 透明度变低、叶子变稀"的问题。草叶和树枝边缘的闪烁来自细小几何体，这正是时间性抗锯齿要解决的。
- **教训：STP 资源在打包时被剥离**。URP 在打包时检查所有管线资源，没有一份的放大滤镜选 STP，就把 STP 的计算着色器从包里删掉（`STPResourceStripper`）。四档 URP 资源原来都是"自动"，运行时再切到 STP，就每帧在 `STP.Execute` 里空引用，画面停在黑屏或上一帧。修法：四档 URP 资源的放大滤镜都存成 STP，打包时保留资源；运行时仍由 `AntiAliasing.Apply` 按所选模式改回"自动"。同时每台相机在渲染前检查一次抗锯齿设置（`beginCameraRendering`），因为游戏场景的相机比设置加载得晚。
- 冒烟测试原来只检查逻辑，截图黑了也会通过。现在加了一项：全程没有任何异常或错误日志才算通过。
- 帧时间测量统一用 `GpuTimer`：关垂直同步，取 FrameTimingManager 的 GPU 帧时间（去掉最慢 10%），同时记录实际帧时间。后来发现 Metal 上这个 GPU 时间约为实际帧时间的 2 倍（包含多帧并行的排队），所以它只用来比较相对高低；对外报告的帧率用实际帧时间。第一次抗锯齿对比三种模式都是 8.3 ms，实际是 120 Hz 刷新率的垂直同步间隔，不是真实开销。

## 超分评估与 GRD（2026-11-23 下午）
- **评估的风动对齐**：第一次跑 UpscaleBench 时，草的风动时钟在配置之间一直往前走，每个配置拍到的草叶位置都不一样，FLIP 主要在量风的相位（同一后端质量档反而比性能档差）。修法：每个配置开始时把风动时钟归零（`EnvController.ResetWindClock`），风照常吹，所以时间性超分仍然要处理真实运动。

- **推荐规则的定义修正**：规则写的是"不超过最佳原生抗锯齿的 110%"。native_off 不是抗锯齿，原来却被算了进去。参考图是不带时间滤波的超采样，FLIP 天然偏向 native_off，但它的闪烁约是 STP 的 2 倍。现在基线只算 native_taa / native_stp，native_off 不参与推荐。这是改定义错误，不是看了结果再调规则；报告里写明了。

## 挂机 GC 排查（2026-11-23 晚，定时任务）

## 爬墙镜头（2026-11-23 晚，定时任务）
- **先查清是什么挡住了镜头**：在冒烟截图那一刻记下镜头和她的位置、附近树冠框、镜头处的碰撞体。结果镜头在塔墙里（冒烟把镜头摆在她侧前方，防遮挡组件因为她离墙太近没把镜头推出来），画面里的树是她头顶那棵。所以主要修法是攀爬时镜头自动转到她身后对着墙，而不是只做"避树"。
- **自动转向只在玩家不动鼠标时**：玩家转过镜头后 1.2 秒内不抢。攀爬的 W/S/A/D 是相对墙的，不受镜头朝向影响，所以转镜头不会改变操作。
- **树冠不加碰撞体，用框检测**：给树冠加碰撞体会影响攀爬射线和角色碰撞；改为生成时记下每棵树渲染包围盒的上 2/3（水平缩到 80%），由 Cinemachine 扩展在 Body 阶段沿"看点 → 镜头"线检测，拉近到第一个树冠前，快进慢出。只在攀爬/翻越/之后 2 秒/离地 3 m 以上时启用，地面走路的取景不变。
- 最近距离 2.6 m：近处抖动淡出（NearFade）在 2.4 m 以内会把她也淡掉。
