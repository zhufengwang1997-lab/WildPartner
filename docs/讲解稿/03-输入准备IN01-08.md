# 输入准备（IN-01 ~ IN-08）

## 一句话
超分算法要"吃"好几样东西：深度、运动向量、抖动、遮罩等等。这一块就是把这些"食材"按规范准备好，并且能在 F3 面板上看到。

## 为什么需要它
像给翻译员准备材料：只给一张截图，他只能猜；同时给上下文、前后几页、哪里是图片不用翻，他才能翻得准。时间性超分要知道每个像素上一帧在哪里（运动向量）、哪些像素不能信历史（遮罩）、什么时候整个画面都换了（重置历史）。

## 怎么做的（逐条）
| 编号 | 内容 | 做法 | 状态 |
|---|---|---|---|
| IN-01 | 按渲染分辨率渲染，不重复抗锯齿 | STP 取代 TAA；FSR 1 / 双线性保留游戏的 TAA | 已验证（冒烟核对渲染尺寸） |
| IN-02 | 深度与 Reversed-Z | 用 URP 深度纹理，F3 显示是否 Reversed-Z | 已验证（Mac 为 Reversed-Z） |
| IN-03 | 运动向量（蒙皮、风动草） | Toon、草、蒙皮网格都写运动向量；F3 可视化 | 已实现，截图已拍 |
| IN-04 | Halton(2,3) 抖动 | 公式和测试在 `UpscalerMath`；内置 STP 用自己的 16 相位序列 | 部分：公式已测，内置后端不用 |
| IN-05 | 曝光 | 游戏是固定曝光 | 不适用 |
| IN-06 | Reactive Mask | 雨、瀑布水雾、蝴蝶星尘登记后画进 R8 遮罩，F3 可视化 | 已实现；当前后端不读它 |
| IN-07 | UI 在放大之后 | UI 画布不经过相机 | 已验证（截图文字清晰） |

## 面试官可能追问
1. **Reactive Mask 做了但后端不读，有什么意义？**
   - 内置 STP 和 FSR 1 都没有遮罩输入，FSR 2/3、DLSS 才有。遮罩先准备好，接原生后端时直接用。
   - 所以 TC-06（关遮罩看雨滴拖影）目前是"未观察到差异"，这是预期的，已如实写明。
2. **粒子为什么不用 `CommandBuffer.DrawRenderer` 画遮罩？** 它不一定支持粒子系统。用渲染层标记加渲染器列表，粒子也能画。
3. **怎么证明草的运动向量对？**
   - F3 运动向量视图：颜色表示方向，亮度表示速度。
   - 草的上一帧位置用上一帧的风动时间算，所以静止镜头下风吹草动也有正确的运动向量。
4. **为什么内置 STP 不用 Halton？** 抖动在 URP 内部，换序列要改 URP 源码。我们的接口 `GetJitter` 如实返回 STP 实际用的序列。
5. **分辨率变化时 IN-08 怎么触发？** 每帧开始前比较窗口尺寸，变了就重新初始化并清历史。冒烟用改窗口大小来测。

## 坦白清单
- 遮罩、Halton 抖动都是给未来原生后端准备的，当前后端没有用上。
- PRD 自检里"用帧调试器确认 RT 尺寸"改成了冒烟自动核对 URP 渲染尺寸，没有人工打开帧调试器。
