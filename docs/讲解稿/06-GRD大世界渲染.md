# GRD（GPU 驻留绘制）

## 一句话
想让显卡自己批量画几千棵树，减少 CPU 一个个下指令。开关和测量脚本都做好了，但在 Mac 上打开后我们的卡通着色器画不出来，所以默认关着，结论写"未达成"。

## 为什么需要它
像寄快递：原来每棵树单独打包、单独填一张快递单（Draw Call）；GRD 把同样的树装进一个大箱子，一张单子发走。树越多，省下的 CPU 时间越多。

## 怎么做的
1. **前提都配好了**：
   - Forward+ 渲染路径；
   - 四档管线资源都存成开启 GRD（避免打包时被剥离，同 STP 的教训）；
   - BatchRendererGroup 变体全保留；
   - Toon 着色器的参数都在材质常量缓冲里，每个 Pass 都引入了 DOTS 变体。
2. **开关**：
   - 启动参数 `-grd=on|off`、`-occlusion=on|off`；
   - 设置菜单两项；
   - F3 面板一个按钮，并实时显示 Draw Calls / Batches / SetPass。
3. **测量脚本**：`tools/grd.sh` 把游戏启动两次（关、开），同样四个机位采样，自动出报告。
4. **出问题后的排查**：
   - 冒烟截图发现树全没了；
   - 关掉遮挡剔除，还是没有；
   - 在镜头前放三个方块：默认材质的方块能画出来，Toon 方块画不出来。
   - 结论：GRD 本身能工作，问题在 Toon 着色器的 DOTS 变体。

## 数据

## 面试官可能追问
1. **为什么不继续修？** 按 45 分钟时间盒，排查到"是哪个着色器的问题"就停下了。下一步是用 Xcode 的 Metal 帧捕获看顶点位置，并在 Windows DX12 上试一次。
2. **冒烟测试为什么没发现？** 冒烟原来只检查逻辑和报错日志，树没画出来不会报错。这是第二次遇到"画面错了但测试通过"（第一次是 STP 黑屏）。现在冒烟会截图，但"画面完整"还需要人看。
3. **哪些东西本来就不走 GRD？** 蒙皮生物、自己实例化绘制的草、粒子、UI、用 MaterialPropertyBlock 的物体、水和天空等自定义着色器。清单见报告。
4. **GRD 和超分能一起用吗？** 能，两者在不同阶段：GRD 管"画什么、怎么批量画"，超分管"画完以后怎么放大"。

- 遮挡剔除只验证了能开能关，效果没测。
