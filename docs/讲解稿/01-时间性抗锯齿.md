# 时间性抗锯齿（关 / TAA / STP）

## 一句话
原来游戏完全没有抗锯齿，草叶边缘一闪一闪。现在用"多帧合成"把锯齿和闪烁压下去，三种模式随时可以切换，方便对比。

## 为什么需要它
像拍夜景时手机连拍几张再合成：单张有噪点，几张一叠就干净了。每一帧都把镜头挪动不到一个像素，再把最近几帧按"运动向量"（每个像素上一帧在哪里）对齐后混合，细小的草叶和树枝就不会闪了。

## 怎么做的
1. **三种模式**：关 / TAA（URP 自带，加锐化 0.4）/ STP（Unity 的时间性超分，在原生分辨率下就是"更好的 TAA"）。设置菜单、F3 面板和启动参数 `-aa=` 都能切换，选择会存盘。
2. **前提条件**：相机开后处理、关 MSAA、关动态分辨率、渲染器支持运动向量。每次切换都会把这些强制设好。
3. **草和风的运动向量**：草是 GPU 生成的。运动向量的计算是：用上一帧的风动时间和物体矩阵算一次位置，再用这一帧的算一次，两者相减。否则草一摆动，时间性抗锯齿就会拖影。
4. **镜头切换清历史**：进出木屋是瞬移，上一帧的画面和这一帧完全无关，必须清空历史帧，否则会叠出残影（IN-08）。
5. **按画质档给默认值**：低档用 TAA，其余用 STP。

## 数据
- 冒烟测试验证三种模式都生效到相机和管线。
- 测量方法：特效开销清单 `docs/特效开销清单.md`，四个机位，关垂直同步，帧时间是相对值。
  - STP 比 TAA 多 0 到 0.14 ms，在测量噪声（约 ±0.2 ms）以内；
  - SSAO 1.3–3.8 ms，是最贵的一项；
  - 草地 0.7–1.4 ms。

## 面试官可能追问
1. **踩过什么坑？**
   - 打包后 STP 黑屏，每帧在 `STP.Execute` 里报空引用。
   - 原因是 URP 打包时会检查所有管线资源，发现没有一份选了 STP，就把 STP 的计算着色器从包里删掉（`STPResourceStripper`）。我们是运行时才切到 STP 的，所以没被它看到。
   - 修法：四档管线资源都存成 STP，运行时再按需改回。
   - 教训写进了 DECISIONS。冒烟测试也加了一条"全程不能有任何错误日志"，因为原来截图黑了测试也照样通过。
2. **为什么第一次测出来三种模式都是 8.3 ms？**
   - 当时开着垂直同步，帧时间被锁在 120 Hz。改成关垂直同步，并用 GPU 计时。
   - 后来又发现 Metal 上 FrameTimingManager 的 GPU 时间约为帧时间的 2 倍（多帧并行），所以只当相对值用。
3. **镂空草叶的 mipmap 覆盖率问题怎么处理的？**
   - 检查过，项目里没有"透明贴图 + Alpha Clip"的植被。草是几何草叶，树是实心网格，所以不存在这个问题。
4. **TAA 和 STP 有什么区别？**
   - TAA 是混合加锐化。STP 用更复杂的重建，还能同时把低分辨率放大。所以 STP 是我们超分的时间性后端。

## 坦白清单
- 鬼影的定量对比没有做。时间稳定性只在静止场景测了相邻帧差（见超分评估报告）。
