# 统一超分接口（com.zfw.upscaling）

## 一句话
一个"万能插座"：游戏只认这一个接口，背后接 STP、FSR、渲染缩放，以后还能接 DLSS、MetalFX，游戏代码一行不改。

## 为什么需要它
像手机充电口统一成 USB-C：以前每个品牌一种插头，换手机就要换线。超分技术也是每家一套接口：NVIDIA 的 DLSS、AMD 的 FSR、苹果的 MetalFX、Unity 自己的 STP。如果游戏直接调用某一家，换平台就得改游戏代码。统一接口把"游戏"和"具体用哪家"分开。

## 怎么做的
1. **接口 `IUpscaler`**：七个方法，按说明书 FR-UP-01 定义。
   - `Initialize`：给它显示分辨率和档位，它返回"内部用多大分辨率渲染"。这是所有低分辨率画面尺寸的唯一来源。
   - `GetJitter`：抖动。每帧把镜头偏移不到一个像素，让多帧合起来能还原细节。
   - `GetMipBias`：Mip 偏移。告诉贴图采样"按高分辨率挑贴图清晰度"，不然低分辨率渲染时贴图会糊。
   - `RecordPass`：在 Unity 的渲染图（Render Graph，一张描述"这一帧要做哪些步骤、读写哪些图"的流程表）里登记放大步骤。
   - `ResetHistory`：清空历史帧，用于镜头切换。
2. **三个后端**，都基于 Unity URP 自带的能力：
   - STP：Unity 自研的时间性超分，用多帧信息补细节。
   - FSR 1：AMD 的空间超分，单帧放大加锐化。
   - 渲染缩放：最简单的双线性放大，作为保底。
3. **`UpscalerHost`**：运行时管家。窗口尺寸一变就重新初始化；每台相机渲染前把设置推上去；镜头切换时转发"清空历史"。
4. **程序集隔离**：游戏的程序集定义里不能出现任何厂商 SDK 的名字。有一个自动测试专门检查这一条（约束 C3）。

## 数据
- EditMode 单元测试 7/7 通过。
- 冒烟测试（Mac 包）验证了三件事：
  - 三个后端 × 质量 / 性能两档，URP 实际渲染宽度都等于 `Initialize` 的返回值；
  - 连续切换 50 次没有任何报错；
  - 窗口从 1600×900 改到 1280×720 再改回来，渲染尺寸 941×529 → 753×424 → 941×529，每次都重新初始化。
- 出处：`Logs/smoke/smoke_result.txt`、`Packages/com.zfw.upscaling/Tests/Editor/`。

## 面试官可能追问
1. **URP 自己已经有 `IUpscaler` 了，为什么还要自己写？**
   - URP 6.3 的那套在 `ENABLE_UPSCALER_FRAMEWORK` 宏后面，是实验接口，默认关闭。
   - 我们的接口放在自己的命名空间 `Zfw.Upscaling`，不依赖它。
   - 以后接原生插件时，可以让后端同时实现两套接口。
2. **内置后端的 `RecordPass` 是空的，这算不算偷工？**
   - 这是有意的最小偏离，已写进 DECISIONS 和接入规范。URP 自己在后处理末尾记录放大 Pass，我们再记一次就会重复。
   - 但"渲染尺寸唯一来源"这条我们用测试守住了。
3. **怎么证明加后端不用改游戏层？**
   - STP 后端就是后加的（说明书里没有）。
   - 游戏层只用 `UpscalerSelector` 和 `UpscalerHost`；设置菜单的方案列表来自 `Available()`，新后端会自动出现。
4. **分辨率变化时会怎样？**
   - 每帧开始前比较窗口尺寸，变了就重新 `Initialize`，并清空历史帧。冒烟测试覆盖了这一点。
5. **为什么要 Mip 偏移减 1？**
   - 低分辨率渲染时，GPU 会按渲染分辨率挑较糊的贴图层级。偏移 log2(渲染/显示) 是把它拉回显示分辨率应有的层级。
   - 再减 1 是说明书的建议：给时间性超分多留一点细节。

## 坦白清单
- DLSS、MetalFX、FSR 2/3 没有实现，只有设计（`docs/设计方案/`）。原因是 URP 17 没有内置，需要原生插件，时间不够。
- 内置 STP 用的是它自己的 16 相位抖动，不是说明书要求的 Halton(2,3)。Halton 公式已实现并测试，留给原生后端。
