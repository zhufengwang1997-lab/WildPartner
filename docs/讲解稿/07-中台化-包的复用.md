# 项目二的包如何复用（"中台化"）

## 一句话
画质分级、能力探测、性能采集这三块，在项目二《矿坑余烬》里写成独立的 Unity 包；本项目直接按 Git 标签引用，没有复制代码。

## 为什么需要它
像连锁店的中央厨房：酱料只在一处做，各门店按批次领。改配方时只改中央厨房，门店换一下批次号就行。

## 怎么做的
1. **三个包**：`com.zfw.gpucaps`、`com.zfw.qualitytiers`、`com.zfw.perfrunner`，都放在 MineEmbers 仓库。WildPartner 的 `Packages/manifest.json` 用 Git URL 加标签引用它们。
2. **扩展而不是改包**：画质分级包只管通用字段（光源、粒子、泛光、雾），留了 `TierExtension` 扩展点。本项目用 `WildPartnerTier` 加草地、LOD、SSAO、湖面反射，包本身不动。
3. **要改包时按版本走**：这次给 GpuCaps 加超分字段，是在 MineEmbers 里改、升 schema 2、打 `v0.3.0` 标签，WildPartner 再把引用从 `v0.2.0` 换成 `v0.3.0`。
4. **新包也按同样方式做**：超分中间件 `com.zfw.upscaling` 是一个独立包，有自己的程序集、测试和接入规范，可以搬到别的项目。

## 数据
- 提交记录：MineEmbers `e275945`（schema 2，标签 v0.3.0）；WildPartner 的 manifest 引用随之更新。
- 画质分级扩展：冒烟逐档验证（`docs/画质分级.md`）。

## 面试官可能追问
1. **包里有 bug，两个项目都用，怎么办？** 在包仓库修，打新标签。两个项目各自决定什么时候升级，互不影响。
2. **为什么不用 Unity 的 Asset Store 包或者 npm 私服？** 个人项目用 Git 标签最简单，Unity 原生支持。团队里会换成私有 scoped registry。
3. **扩展点为什么用 `SerializeReference`？** 它能让一个列表里存不同的子类，每个游戏加自己的字段，包不用知道具体类型。
4. **schema 升级怎么兼容旧报告？** 新字段都是可选的。合并工具 `caps_merge.py` 同时接受 1 和 2。
5. **怎么保证包不依赖游戏？** 包的程序集只引用 Unity 和其他包，有测试检查游戏程序集不引用厂商 SDK。
