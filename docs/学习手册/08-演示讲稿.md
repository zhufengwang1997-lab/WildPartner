## 逐段讲稿

### 0:00–0:30 开场

**操作**：启动游戏，女巫在木屋床上醒来。走出木屋，看前院和远山。

**说**：
> "这是我用 Unity 6.3 URP 做的一个小型探索游戏，卡通风格，着色器都是手写的。游戏本身是试验田，我今天主要展示上面做的超分中间件和评估工具。"

### 0:30–1:30 抗锯齿对比

**操作**：站到草地上，镜头对着草和树。F3 面板依次点"关 / TAA / STP"（或按 F4 循环）。

**说**：
> "关掉时草叶和树枝边缘有锯齿、会闪。TAA 平滑但略软，我加了 0.4 的锐化。STP 是 Unity 的时间性超分，原生分辨率下它就是一个更好的 TAA。面板上同时有帧时间。"

**注意**：帧时间读数会跳，不要念具体数字，数字留到最后讲报告。

### 1:30–3:00 超分切换（核心）

**操作**：F3 面板切超分方案 STP → FSR 1 → 渲染缩放；再切档位 质量 → 平衡 → 性能。

**说**：
> "游戏只调用一个接口 `IUpscaler`。选择器按 DLSS、MetalFX、STP、FSR1、渲染缩放的顺序挑第一个这台机器能用的。这台 Mac 上 DLSS 和 MetalFX 还没有实现，所以自动选 STP。
> 看这一行：渲染分辨率跟着档位变。质量档每边是 1/1.5，性能档是一半。
> 界面文字一直是清楚的，因为 UI 在放大之后按显示分辨率画。
> 加一个新后端不用改游戏代码。STP 本身就是后加的。"

**可选（如果时间够）**：按 F1 切到窗口模式再切回来，说"切分辨率时渲染尺寸自动重算、历史帧清空，日志里有记录"。

### 3:00–3:45 输入可视化 + 历史重置

**操作**：
1. F3 输入视图切"运动向量"，跑几步：人物、猫、摆动的草有颜色。
2. 切"Reactive Mask"：如果在下雨，雨丝和瀑布水雾是亮的。
3. 走到木屋门口按 E 进屋。

**说**：
> "时间性超分要知道每个像素上一帧在哪。风吹的草是顶点动画，物体本身没动，我把上一帧的风时钟也传进着色器，重算一遍。去掉运动向量画质误差会大 26%。
> 雨这种透明粒子没有可靠的运动向量，我把它们画进一张 Reactive Mask，告诉超分这里少信历史。目前 STP 不读这张图，留给以后接 FSR2 和 DLSS。
> 进门是一次镜头硬切，会触发历史重置，所以屋里不会残留门外的画面。"

### 3:45–5:00 数据

**操作**：切到 `docs/超分评估报告-mac-20261123.md`，指散点图和逐场景表；再看一眼 `docs/特效开销清单.md`。

**说**：
> "评估是一条命令跑出来的：6 个固定场景、15 种配置，用 FLIP、SSIM、PSNR 比画质，再测帧率。参考图是 2 倍超采样。
> 同一设置拍两次的差是 0.074，这是噪声底，所以我主要看排序：STP 质量档在 6 个场景里都比 FSR1 和渲染缩放好。
> 帧率提升：质量档 33% 到 42%，需求是 40%，只有渲染缩放达到。我推测是接近 CPU 瓶颈，还没有用 Profiler 拆开验证。
> 按规则推荐 STP 平衡档。
> 特效开销表测出 SSAO 和草是两大开销，和画质档位的设计一致。
> GRD 在 Mac 上没跑通，物体不显示，最小场景也复现，所以默认关闭，报告里写的是未达成。"

## 演示出问题时怎么办

| 情况 | 处理 | 说什么 |
|---|---|---|
| 游戏打不开 / 崩溃 | 换用 `docs/screenshots/` 里的截图和对比图讲，直接跳到"数据"环节 | "现场环境出了问题，我用测试时自动截的图来讲，这些图都是冒烟测试和评估脚本生成的。" |
| 误点了"开 GRD"，物体都消失了 | F3 再点一次"关 GRD" 即可恢复 | 顺势讲：这就是 GRD 在 Mac 上的问题，最小场景也复现（05 案例 3） |
| 画面黑屏或卡在上一帧 | F3 把超分方案切到"渲染缩放"或抗锯齿切"关"；还不行就重启游戏 | "这是我之前遇到过的 STP 资源问题的症状，已经修过；我先切到渲染缩放继续。"（不要说已经修好又出问题，先恢复再说） |
| 帧时间读数忽高忽低 | 不念具体数字 | "实时读数受后台程序影响，可信的数字在报告里，是关垂直同步、去掉最慢 10% 测的。" |
| F3 面板没显示 | 按 F3（它是开关） | — |
| 窗口太小、UI 挤 | 按 F1 切到全屏窗口 | 可以顺带讲 F1 切换会让超分重算尺寸 |
| 不下雨，看不到 Reactive Mask | 跳过，口头讲 | "下雨时雨丝和瀑布水雾在这张图里是亮的。" |
| 进门后有一瞬残影 | 如实说 | "SC-05 只检查了切换后第 20 帧，最初几帧没有单独检查，这是一个已知的测试缺口。" |
| 时间不够 | 砍掉"输入可视化"，保留"超分切换"和"数据" | — |
| 面试官要看 Windows | 说明 Windows 两台机器的基准结果还在测；1070 Ti 上手动试玩过能跑、超分能切换 | 不要说具体 Windows 数字（还没有） |

## 演示里**不要**说的话

- 不说"帧率提升 50%"。只有 STP 性能档到了 +53%，质量档是 33–42%。
- 不说"Draw Call 降低 60%"。没有可信数据。
- 不说"支持 DLSS"。只有设计文档。
- 不说"做了光追原型"。只有可行性分析。
- 不说 Windows 上的具体帧率。还没有数据。
