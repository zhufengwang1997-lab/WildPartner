## 1. 游戏流程与存档

**职责**：决定启动时先初始化什么、玩家现在处在哪个状态（游玩 / 暂停 / 地图 / 图鉴 / 主菜单），以及把进度和设置写到硬盘。

**对外接口**：
- `GameFlow`：`Pause()`、`Resume()`、`OpenMap()`、`OpenJournal()`、`BackToMenu()`、`Continue()`、`NewGame()`。
- `SaveSystem`：两份 JSON，一份是游戏进度（抓到了什么、当前宠物、连续雨夜数），一份是设置（画质档、抗锯齿、超分、显示模式、音量……）。

**流程**：`Bootstrap.Awake`（`Core/Bootstrap.cs:26`）先把主菜单相机关掉，再依次初始化：画质档（启动参数 `-tier=` > 存档 > 默认"高"）→ 档位扩展 → 抗锯齿 → 超分 → 超分输入 Pass → GRD → 显示设置。`GameFlow.Start` 等一帧后直接 `NewGame()`，女巫在木屋床上醒来。

**依赖**：几乎所有系统都读 `SaveSystem.Settings`。

**打个比方**：剧院的舞台监督。灯光、音响、演员上场的顺序由他喊，自己不演戏。

**岗位关注点**：
- **初始化顺序会变成画面问题。** 开场"镜头飞一圈"的穿模：主菜单相机在场景里的优先级是 20，Cinemachine 第一帧从优先级最高的相机混合过来，飞了 2 秒。修法是在 `Awake` 里把它直接关掉，不靠事后改优先级（`Core/Bootstrap.cs`）。
- **设置字段要向后兼容。** 旧字段 `grd` 默认 true，已经写进玩家的旧设置文件。所以新开 `grdEnabled`（默认 false），不复用旧字段（DECISIONS「超分评估与 GRD」）。

## 2. 玩家与镜头

**职责**：
- 女巫的移动：走、跑、跳、游、爬、骑。
- 程序化动画和头发、裙摆的二次摆动。
- 第三人称镜头：Cinemachine 3 加两个自定义扩展（防遮挡、树冠避让）。

**对外接口**：
- `PlayerController.Teleport(pos, rot)`：瞬移。
- `PlayerController.CameraCut`：静态事件，"镜头发生了不连续跳变"（`Player/PlayerController.cs:107` Teleport、`:114` 触发、`:138` 声明）。

**流程**：每帧读输入，所有移动方式都经过同一个 `GuardWorld`（越界、掉出地形 3 秒回安全点），之后 Cinemachine 算镜头。

**依赖**：GameInput（Input System）、WorldLayout（地形高度、水深）、Cinemachine。

**打个比方**：`CameraCut` 就像电影剪辑时的"硬切"。剪辑师要告诉调色师"这里换镜头了，别把上一镜的颜色带过来"。超分的"历史帧"就是那个"上一镜"。

**岗位关注点**：
- **任何瞬移都要喊一声 `CameraCut`。** 进出木屋（`World/CabinInterior.cs:154`）、传送都会触发。`Core/Bootstrap.cs:54` 把它接到 `AntiAliasing.ResetHistory`。漏一处，时间性超分就会把上一位置的画面当历史混进来，出现残影。
- **二次摆动在动画之后跑**（`Player/SecondaryMotion.cs:78` 附近）。它改的是骨骼位置，所以蒙皮网格的运动向量也包含了头发和裙摆的摆动（Unity 蒙皮网格会自己保存上一帧的位置）。

## 3. 世界与环境

**职责**：
- **地形**：360 m × 360 m（`WorldLayout.Size = 360`），运行时生成网格。
- **河流和湖**：河流、湖、瀑布。
- **植被**：摆放表约 3.2 万个实例，Prefab + LOD Group。
- **昼夜和天气**：`EnvController`、`Weather`。
- **风**：给着色器的全局参数 `_WP_Wind`、`_WP_WindTime`、`_WP_WindTimePrev`。

**对外接口**：
- `EnvController.ResetWindClock()`：评估时让每个配置的草从同一个风相位开始。
- `WorldLayout.RiverFlow`：一张流速系数表，水面着色器、漂浮物、鱼群、游泳推力共用。
- `GrassRenderer.Instance`。

**流程**：
- `EnvController` 每帧推进游戏时间，算太阳角度、颜色和雾。
- 它还推进风时钟。**上一帧的风时钟也要传给着色器**，运动向量要用。
- `WaterProbe` 时间切片刷新反射探针（每帧一个面）。

**依赖**：渲染模块（着色器读这些全局参数）。

**打个比方**：舞台布景组。布景本身不复杂，但每个会动的东西（草、树、水）都要告诉摄影师"我上一秒在哪"，否则后期没法对齐。

**岗位关注点**：
- **会动的顶点要能算出"上一帧的位置"。** 风是顶点动画，物体本身没移动，Unity 默认认为它的运动向量是 0。所以把 `_WP_WindTimePrev` 也传进着色器，MotionVectors Pass 用上一帧的时间再算一次风偏移。
- **水面反射选反射探针，不选 SSR**（DECISIONS C2）。原因：
  - URP 没有内置 SSR，自己写要多一个全屏 Pass。
  - 低角度看水时屏幕外的东西会缺。
  - 超分时会多一个不稳定来源。
- **探针不每帧刷新。** 刷新时机：开局、游戏时间每 15 分钟、天气变化。每帧只刷一个面，128 px。

## 4. 生物与玩法

**职责**：动物 AI（视觉、听觉感知，警觉，逃跑）、施法捕捉、钓鱼、宠物轮换（猫 / 锦鲤 / 月影蝶）和图鉴。

**和图形相关的只有两点**：
1. 生物是蒙皮网格，**不走 GRD**（GRD 不支持 SkinnedMeshRenderer），走 SRP Batcher。
2. 月影蝶翅膀发光、月光花用 MaterialPropertyBlock 改参数。GRD 遇到 MaterialPropertyBlock 会退回普通绘制，数量少就保留（`docs/GRD评估报告.md`「不走 GRD 的物体」）。

**打个比方**：演员。图形组只关心他们的戏服（材质）会不会让灯光组（批处理）多干活。

## 5. 渲染与着色器（重点）

### 5.1 职责

全部手写的卡通着色器，加上 URP 的设置：
- **Forward+ 渲染器**（`Assets/Settings/PC_Renderer.asset`）。
- **SSAO**：AfterOpaque。
- **高度雾**：用 FullScreenPassRendererFeature 实现，编辑器脚本 `Editor/RenderFeatures.cs`。
- **四档 URP 管线资源**：`Assets/Settings/URP_*.asset`。

| 着色器 | 行数 | 用在哪 | 有没有 MotionVectors Pass |
|---|---|---|---|
| `Toon.shader` + `ToonCommon.hlsl` | 405 + 98 | 女巫、动物、树、岩石、木屋、道具 | ✅ 有（`:337`） |
| `Grass.shader` | 291 | GPU 实例化草 | ✅ 有（`:268`） |
| `ToonTerrain.shader` | 193 | 地形 | 没有（地形不动，用相机运动算） |
| `Water.shader` | 223 | 河、湖 | 没有（透明） |
| `Waterfall.shader` | 105 | 瀑布水帘 | 没有，登记进 Reactive Mask |
| `Sky.shader` / `FarRidge.shader` | 84 / 80 | 天空 + 云、远山 | 没有 |
| `HeightFog.shader` | 64 | 全屏高度雾 | — |

### 5.2 Toon 着色器的结构（`Assets/_Game/Shaders/Toon.shader`）

一个着色器 5 个 Pass，每个 Pass 是 URP 在不同阶段来"借用"的：

| Pass | 行号 | 谁来调用 | 干什么 |
|---|---|---|---|
| ForwardLit | `:41` | 主渲染 | 卡通光照：N·L 分成 `_RampSteps` 档色阶，阴影偏蓝紫，加边缘光，加附加光源 |
| ShadowCaster | `:183` | 阴影 Pass | 把自己画进阴影贴图（风动也要算，否则影子不动） |
| DepthOnly | `:242` | 深度预渲染 | 只写深度 |
| DepthNormals | `:288` | SSAO | 写深度 + 法线 |
| MotionVectors | `:337` | 超分 / TAA | 写"这个像素从上一帧到这一帧移动了多少" |

**ForwardLit 里的要点**：
- 色阶：`:111–115`，把 0–1 的光照量化成几档平色，档与档之间用 `smoothstep` 软化。
- 法线：`:131`，`SafeNormalize`。这是"门发光"事故以后改的，零法线不再变成 NaN，见 05 手册案例 1。
- 边缘光：`:153`，室内由全局参数 `_WP_RimOff` 关掉。

**三条"兼容性"**（GRD 和批处理要求的）：
1. **SRP Batcher 兼容**：所有材质参数放在 `CBUFFER_START(UnityPerMaterial)` 里（`ToonCommon.hlsl:11–29`），每个 Pass 看到的参数布局完全一样。
2. **DOTS Instancing 兼容**：`ToonCommon.hlsl:31–35`，`_BaseColor` 声明成 DOTS 实例属性。GRD 用 BatchRendererGroup 画，需要这个。
3. **运动向量**：MotionVectors Pass 同时处理三种运动。
   - **物体本身移动**：用上一帧的模型矩阵。
   - **蒙皮动画**：`unity_MotionVectorsParams.x == 1` 时用 Unity 提供的上一帧顶点位置 `positionOld`。
   - **风**：用上一帧的风时钟 `_WP_WindTimePrev` 再算一次风偏移（约 `:381`，`ApplyWindOSPrev`）。

**打个比方**：一个演员（着色器）要同时会演正戏（ForwardLit）、当替身（ShadowCaster）、站位走台（Depth）和给剪辑师写场记（MotionVectors）。场记写错了，后期（超分）就会把画面拼歪。

### 5.3 草（`World/GrassRenderer.cs` + `Grass.shader`）

- **划分**：地面按 7 m 一块分区，每块 28 × 28 格，每格 0.25 m 一丛草。
- **提交**：每帧把镜头附近的块用 `Graphics.RenderMeshPrimitives` 提交（`:225`），一次调用画一整块里的所有草丛，这就是 GPU 实例化。Unity 按每块的包围盒做视锥剔除。
- **形状在 GPU 上算**：草叶形状在顶点着色器里由格子哈希算出（`BuildBlade`），CPU 不存每根草。
- **运动向量**：`RenderParams.motionVectorMode = Object`（`:201`）。MotionVectors Pass（`Grass.shader:268`）用上一帧风时钟再造一次草叶（`:281`），乘上一帧的视图投影矩阵 `_PrevViewProjMatrix`（`:284`）。
- **画质档**：只改 `grassQuality`（距离和密度）。

### 5.4 岗位关注点

- **每个自定义着色器都要回答四个问题**：能不能进 SRP Batcher？有没有 DOTS 变体？有没有运动向量？透明的话要不要进 Reactive Mask？这就是"图形平台"要给美术和 TA 定的规范。本项目写进了《超分技术接入规范》。
- **NaN 会被后处理放大。** 一个像素是 NaN，Bloom 会把它扩成一大团白光；TAA / STP 会把它带进历史帧，拖好几帧。所以 `normalize` 换成 `SafeNormalize`，冒烟测试也加了"室内网格不能有零或 NaN 法线"。
- **哪些物体没做 DOTS 变体，要说得出来**：地形、水、天空、远山。理由是每样只有一两个物体（GRD 报告里有表）。

## 6. 抗锯齿（`Rendering/AntiAliasing.cs`）

**职责**：在"关 / TAA / STP"三种模式之间切换，并保证切换时前提条件都满足。

**对外接口**：
- `Apply()`（`:64`）、`ApplyTo(cam)`（`:79`）。
- `ResetHistory()`（`:95`）。
- `Supported(mode)`：STP 需要 compute shader。

**流程**：`Hook()`（`:49`）挂到 `beginCameraRendering`（`:53`），每台相机渲染前强制设好这些：开后处理、关 MSAA、关动态分辨率、渲染器支持运动向量。

**关键知识**：
- URP 17 里把 `upscalingFilter` 设成 STP，即使渲染比例 100% 也会跑 STP，STP 取代 TAA。所以"原生 STP"就是一个更好的 TAA；以后降分辨率，只要改渲染比例。
- TAA 模式加了对比度自适应锐化 0.4；STP 没有锐化参数。

**打个比方**：TAA 像拍照时连拍几张再叠起来去噪，每张相机都稍微抖一下（抖动），叠出来边缘更平滑。STP 是更聪明的叠法，还能顺便把小图放大。

**岗位关注点**：**打包会剥离没用到的资源。** 四档 URP 资源原来都是"自动"，运行时才切到 STP，打包时 URP 认为没人用 STP，就把 STP 的计算着色器删了，运行时黑屏。修法：四档资源都存成 STP，运行时再改回去（05 手册案例 2）。

## 7. 超分中间件 `com.zfw.upscaling`（核心）

### 7.1 职责

让游戏只跟一个接口打交道，背后可以换成任何超分算法。游戏代码里不出现任何厂商 SDK 的名字，单元测试 `GameDoesNotReferenceVendorSdks` 专门检查这一点。

### 7.2 结构

```
Packages/com.zfw.upscaling/
├─ Runtime/
│  ├─ IUpscaler.cs          接口 + 输入结构 UpscalerInputs
│  ├─ UpscalerSelector.cs   按顺序挑第一个可用的后端
│  ├─ UpscalerHost.cs       持有当前后端；渲染尺寸的唯一来源
│  ├─ UpscalerMath.cs       缩放比例、渲染尺寸、MipBias、Halton 抖动
│  └─ Backends/UrpBuiltinUpscaler.cs   STP / FSR1 / RenderScale 三个后端
├─ Tests/Editor/UpscalingTests.cs      7 个 EditMode 测试
├─ Tools~/quality_eval.py、bench_report.py   评估脚本（FLIP/SSIM/PSNR、出报告）
└─ Documentation~/超分技术接入规范.md
```

### 7.3 接口（`IUpscaler.cs:18`）

| 方法 | 含义 | 内置后端怎么实现 |
|---|---|---|
| `IsSupported(caps)` | 这台机器能不能用 | STP 看 `STP.IsSupported()`（要 compute shader） |
| `Initialize(display, quality)` → 渲染尺寸 | 显示尺寸 + 档位 → 渲染尺寸 | `UpscalerMath.RenderSize` |
| `GetJitter(frame)` | 这一帧的亚像素抖动 | STP 返回 URP 自己的 16 相位序列 `STP.Jit16`；空间后端返回 0 |
| `GetMipBias()` | 贴图要多清晰 | log2(渲染宽/显示宽) − 1 |
| `RecordPass(graph, inputs, output)` | 把放大 Pass 记进渲染图 | **空的**：URP 自己在后处理末尾记 |
| `ResetHistory()` | 清空历史帧 | 下一次相机渲染时设 `resetHistory = true` |

### 7.4 一帧里怎么跑

1. **启动时**：`UpscalerSelector.Select`（`:48`）按 `DLSS → MetalFX → STP → FSR1 → RenderScale`（`:20`）挑第一个可用的。玩家选择优先，启动参数 `-upscaler=` 再覆盖它。档位按画质档映射：低 → 性能，中 → 平衡，高/极高 → 质量（`:34`）。
2. **`UpscalerHost.Reinit`**（`:55`）：调 `Initialize` 得到渲染尺寸，**这是全项目唯一算渲染尺寸的地方**。然后把它换成 `renderScale` 写进 URP 管线资源（`Configure`，`UrpBuiltinUpscaler.cs:47`）。
3. **每一帧开始**（`beginContextRendering`，`UpscalerHost.cs:69`）：如果窗口尺寸变了，就重新 `Reinit`。
4. **每台相机渲染前**（`ConfigureCamera`，`UrpBuiltinUpscaler.cs:56`）：设 TAA 模式、`mipBias`，必要时设 `resetHistory`。
5. URP 画场景（渲染分辨率）→ 后处理 → URP 自己的放大 Pass → 界面按显示分辨率画在最上面。

### 7.5 打个比方

超分中间件像一个**万能电源插座转换器**。游戏是电器，只认一种插头（`IUpscaler`）。到了哪个国家（哪块显卡），转换器自动选当地的插座（DLSS / MetalFX / STP / FSR）。电器不用改。

### 7.6 状态（老实说）

| 项 | 状态 |
|---|---|
| STP / FSR 1 / 渲染缩放 三后端 | ✅ Mac M5 Max 实测；Windows 1070 Ti 用户目测可切换、有效果（还没有基准数据） |
| 自动选择 + 玩家选择 + 启动参数 | ✅ EditMode 7/7 |
| 窗口尺寸变化 / 切显示模式时重算尺寸 + 清历史 | ✅ 冒烟（M5 Max）：1366×768 → 渲染 804×452；全屏 3456×2234 → 2033×1314 |
| Halton(2,3) 抖动和相位数公式 | 🟡 写了、单元测试过，但**运行时没有后端用它**。STP 用 URP 自带序列，空间后端不抖。留给以后的原生后端（DLSS / FSR2） |
| MipBias 传给 URP | 🟡 设了 `taaSettings.mipBias`；URP 在 STP 路径里是否用这个值 ❓ 待确认 |
| DLSS / MetalFX / FSR 2/3 | 📄 只有设计文档 `docs/设计方案/FSR2-3与DLSS-MetalFX后端.md` |

### 7.7 岗位关注点

- **"渲染尺寸只有一个来源"。** 如果游戏层、URP、超分各算各的，就会出现 UI 位置错、贴图糊、抖动幅度不对。冒烟测试核对 URP 实际渲染宽度与 `Initialize` 返回的一致。
- **内置后端 `RecordPass` 为空，这是对需求的"最小改动"，要能解释。** URP 17 的放大由它自己在后处理末尾做。SRP Core 里的 `IUpscaler` 框架被 `ENABLE_UPSCALER_FRAMEWORK` 关着（实验性），所以我们的接口放在自己的命名空间 `Zfw.Upscaling`。
- **加一个后端不改游戏代码**（NFR-05）：STP 本身就是后加的，证明了这一点。

## 8. 超分输入：运动向量 + Reactive Mask

**职责**：给时间性超分准备"额外信息"：
1. **运动向量**：每个像素上一帧在哪。由各着色器的 MotionVectors Pass 写，URP 汇总成一张图。
2. **Reactive Mask**：一张"这里别太相信历史帧"的遮罩，标出雨丝、瀑布水雾、星尘这些透明、没有运动向量的东西。

**接口**：
- `ReactiveMaskSources.Register(renderer)`：登记时把这个物体的运动向量设成 `ForceNoMotion`，并打上渲染层第 7 位（`LayerBit 7`）。
- `UpscalerInputsPass`：一个渲染器特性。
  - 在 `BeforeRenderingPostProcessing` 画遮罩（`:39`、`:54` MaskPass），用 `FilteringSettings.renderingLayerMask` 只画第 7 层（`:71`）。
  - 在 `AfterRenderingPostProcessing` 提供可视化（`:40`）。

**为什么用"渲染层 + 渲染器列表"画遮罩，不用 `CommandBuffer.DrawRenderer`**：后者不一定支持粒子系统，而雨、星尘都是粒子（DECISIONS「超分中间件」）。

**状态**：
- 运动向量 ✅：Mac 实测。TC-05 去掉物体运动向量后 FLIP 从 0.1202 升到 0.1518（+26%），说明运动向量真的在起作用。
- Reactive Mask 🟡：已生成，F3 里能看；**当前三个后端都不读它**（STP 和 FSR1 没有这个输入）。留给 FSR2 / DLSS。

**打个比方**：
- 运动向量是给每个像素贴的"搬家地址单"：我从哪来。
- Reactive Mask 是一张"易碎品"标签：这一块画面变化快，别用老照片去补。

**岗位关注点**：没有运动向量的东西（风动的草、蒙皮动画），在时间性超分里会拖影或糊。所以"新着色器必须带 MotionVectors Pass"是接入规范的一条。

## 10. GPU 驻留绘制（GRD）

**职责**：让 Unity 6 的 GPU Resident Drawer 接管静态网格的绘制。它用 BatchRendererGroup，把很多次绘制合成很少的几次，配合 GPU 遮挡剔除。

**做了什么**：
- Forward+。
- 四档资源都存成 GRD 开启，防剥离，同 STP 的教训。
- BRG 变体全保留。
- Toon 着色器 DOTS 兼容。
- 开关三处都能改：启动参数 `-grd=` / `-occlusion=`、设置菜单、F3 面板。
- 度量脚本 `tools/grd.sh`。

**状态**：
- ❌ **Mac 上未达成**：打开后交给 GRD 的物体全都不显示。连"整个游戏关掉、只留一个相机一盏灯两个方块"的最小场景也一样。根因未找到，所以默认关闭。
- Windows（1070 Ti）：用户目测打开 GRD 和遮挡剔除后"有正常效果"。🟡 没有 Draw Call 对比数据。

**打个比方**：原来每棵树都要单独跟 GPU 说一次"画我"（一次 Draw Call）。GRD 是把所有树的名单一次性交给 GPU，让它自己去画、自己判断谁被挡住了。

**岗位关注点**：**排查要有可信的对照组。** 第一次以为是 Toon 着色器的问题，后来发现对照方块用的是粉色错误着色器，根本不走 GRD，对照无效。详见 05 手册案例 3。

## 11. 显示设置（`Rendering/DisplaySettings.cs`）

**职责**：显示模式（全屏窗口 / 独占全屏（仅 Windows）/ 窗口）、分辨率列表、保存；F1 在全屏窗口和窗口之间切换并在屏幕上提示。

**流程**：`Set(mode, w, h)` → 等 2 帧让系统真的改完 → `AntiAliasing.ResetHistory()`（约 `:149`）→ 日志 `[Display] 已生效：显示 WxH，渲染 WxH（后端/档位），历史帧已重置`。超分尺寸由 `UpscalerHost` 每帧检测窗口变化自动重算（第 7.4 节第 3 步）。

**启动参数优先**：命令行有 `-screen-*` / `-popupwindow` / `-window-mode` 时，不套用保存的设置（评估脚本要固定分辨率）。

**状态**：✅ 冒烟测试（M5 Max）：切到 1366×768 → 全屏窗口 → 切回，核对渲染尺寸 = `RenderSize(显示, 档位)`，历史重置 ≥ 3 次。独占全屏只在 Windows 有，🟡 没有自动测试。

**岗位关注点**：**分辨率变化是超分的"重新开机"**：尺寸要重算，历史要清空，否则第一帧用旧尺寸的历史去混新尺寸的画面。

### 13.3 测量方法（面试会追问）

- **帧时间统一用 `GpuTimer`**：关垂直同步，取 FrameTimingManager 的数据，去掉最慢 10%。
  - **Metal 上的 GPU 时间约是实际帧时间的 2 倍**（含多帧并行排队），只能比相对高低。
  - 对外报告的帧率用实际帧时间。
  - 第一次测三种 AA 都是 8.3 ms：那是 120 Hz 的垂直同步间隔，不是开销。教训：测之前先关垂直同步。
- **评估要能复现**：
  - 每个配置开始时把风时钟归零（`ResetWindClock`），否则 FLIP 量的是风的相位。
  - 每个配置开始前 `ResetHistory`（`UpscaleBench.cs:145/:157`）。
- **噪声底**：参考配置拍两次（`ref` 和 `ref2`），两者的 FLIP = 0.0740，就是测试自己控制不住的差异。结论主要看"6 个场景里排序是否一致"，不只看平均值。
- **特效开销**：`EffectCostBench` 每次只关一项（`:113` 起的 Toggle 表），测完恢复。开销 = 基线 − 关掉后。小于 ±0.2 ms 视为测不出。

### 13.4 打个比方

这一套像体检中心：
- 冒烟测试是每天的量体温；
- 超分评估是全面体检、带对照组；
- 噪声底是"同一个人连测两次血压的差"，小于这个差的变化都不能当真。

### 13.5 岗位关注点

- **数字必须能追溯到文件**：报告里每个数都写了出处（`bench_results/...`）。
- **冒烟测试要能抓到"画面错了"**：原来只查逻辑，截图黑了也过。现在加了"全程无异常日志"，GRD 那一步也截图。但"画面完整不完整"仍然要人看截图，这一点要老实说。
- **找 GC 靠 Profiler 数据，不靠猜**：GC 次数 512 → 69（10 分钟挂机，M5 Max），见 05 手册案例 4。

## 14. 声音（`Audio/ProceduralAudio.cs`）

**职责**：音乐、环境声、脚步声、猫叫和呼噜（合成的）。三个类别系数（音乐 / 音效 / 环境）乘以基准音量，主音量走 `AudioListener.volume`。没用 AudioMixer：Unity 不能用代码创建 AudioMixer 资源。

**和图形岗的关系**：很小。被问到 CPU 占用时可以提一句：声音是运行时程序化合成的，会占一些 CPU。❓ 具体占多少待确认（没有单独测过）。
