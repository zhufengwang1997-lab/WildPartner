## 第一组：项目整体（1–4）

### 1. 用一分钟介绍这个项目。
- **是什么**：Unity 6.3 URP 的小型 3D 探索游戏。游戏本身是"试验田"，重点是上面做的**超分中间件**和**评估工具**。
- **超分中间件**：游戏只调一个接口 `IUpscaler`，背后按设备自动选 STP / FSR 1 / 渲染缩放，加后端不改游戏代码。
- **评估工具**：一条命令跑 6 个场景 × 15 个配置，出 FLIP / SSIM / PSNR / 闪烁 / 帧率报告。
- **结果**（M5 Max，2560×1440）：STP 质量档 6/6 场景画质最好，质量档帧率提升 33–42%。
- **老实部分**：GRD 在 Mac 上没跑通；DLSS / MetalFX 只有设计。

### 2. 为什么用一个游戏来做超分，而不是直接用 Unity 示例场景？
- 超分的难点在真实内容：风吹的草、蒙皮动画、透明粒子、镜头硬切。示例场景很难全部覆盖。
- 自己的游戏能控制每个输入：给风加上一帧时钟、给粒子登记 Reactive Mask。
- 也能顺便练平台工作：画质分级、能力检测、性能测量。

### 3. 项目里你最得意的一个设计是什么？
- "**渲染尺寸只有一个来源**"：`UpscalerHost.Reinit` 调 `Initialize`，别处只读结果。
- 窗口拖动、F1 切全屏、改分辨率、换档位，都走同一条路，自动清历史。
- 冒烟测试核对 URP 的渲染比例换算出的宽度和它一致（M5 Max ✅）。

### 4. 项目里最大的遗憾是什么？
- GRD。Mac 上打开后物体全不显示，最小场景也复现，根因没找到。
- 处理：默认关闭，报告写未达成，没拿"物体没画出来所以 Draw Call 少"的数字当成果。
- Windows 1070 Ti 上用户目测 GRD 有效果，所以很可能是 Metal 发布版的问题。🟡 还没有数据。

## 第二组：超分原理（5–11）

### 5. 时间性超分（STP / DLSS / FSR2）和空间超分（FSR1）有什么区别？
- **空间超分**：只看当前一帧，把小图放大再锐化。信息量就是那一帧，细节补不回来。
- **时间性超分**：每帧相机抖一点（亚像素抖动），多帧累积。用运动向量把上一帧的像素"搬"到这一帧对齐，相当于一个像素采了很多次。
- **代价**：需要运动向量、要处理历史失效（鬼影），镜头硬切要清历史。
- **数据**：STP 质量档 FLIP 0.1106，FSR1 质量档 0.1398，6/6 场景 STP 更好（M5 Max）。

### 6. 抖动（Jitter）是什么？为什么用 Halton 序列？
- 每帧把投影矩阵挪不到一个像素，让同一个像素每帧采样到不同位置。
- Halton(2,3) 是低差异序列：点分布均匀、不扎堆，几帧就能覆盖整个像素。随机数会扎堆。
- 相位数 = round(8 × 放大倍数²)：倍数越大，一个显示像素需要更多采样点。
- **老实说**：🟡 Halton 写了、单元测试过，但运行时 STP 用 URP 自己的 16 相位序列，空间后端不抖。Halton 留给以后的原生后端。

### 7. MipBias 为什么要设成负数？公式是什么？
- 小分辨率渲染时，GPU 按小图选 mipmap，会选更模糊的一层。放大后贴图糊。
- 负 MipBias 让 GPU 按"显示分辨率"的标准选更清晰的一层。
- 公式：log2(渲染宽 / 显示宽) − 1。例：50% 渲染 → −1 − 1 = −2。多减的 1 是因为时间性累积还能再恢复细节。
- ❓ 待确认：URP 在 STP 路径里是否使用我们设的 `taaSettings.mipBias`。

### 8. 运动向量是怎么来的？哪些东西容易漏？
- 每个像素：当前帧屏幕位置 − 上一帧屏幕位置。由各着色器的 MotionVectors Pass 写。
- **容易漏的**：
  - 顶点动画（风）：物体没动，Unity 以为运动是 0。我们把上一帧风时钟传进去重算。
  - 蒙皮动画：用 Unity 提供的 `positionOld`。
  - GPU 实例化的草：`RenderParams.motionVectorMode = Object`，Pass 里用上一帧风时钟重造草叶。
  - 透明粒子：没有可靠运动向量，登记进 Reactive Mask。
- **证据**：去掉物体运动向量，SC-01 FLIP +26%（0.1202 → 0.1518，M5 Max）。

### 9. 什么时候必须重置历史？你怎么保证不漏？
- **触发点**：
  - 镜头硬切：进出木屋、传送、掉出地形拉回；
  - 分辨率或显示模式变化；
  - 换超分后端或档位；
  - 换抗锯齿模式或画质档。
- **怎么保证不漏**：玩家控制器只喊一个事件 `CameraCut`，由 `Bootstrap` 接到 `ResetHistory`；所有瞬移都走 `Teleport`。尺寸变化在 `Initialize` 里自带重置。
- **验证**：SC-05 切镜头后第 20 帧无可见残影（M5 Max）；最初几帧没单独查，这是不足。

### 10. Reactive Mask 是什么？你做到了哪一步？
- 一张单通道图，标出"这里别太信历史帧"的区域：雨丝、瀑布水雾、星尘这类透明粒子。
- 做法：
  - 登记时打渲染层第 7 位、关掉它的运动向量；
  - 一个渲染图 Pass 用渲染器列表按这个层画出来。
  - 不用 `CommandBuffer.DrawRenderer`，因为它不一定支持粒子。
- 🟡 遮罩已生成、F3 里能看，但 STP 和 FSR1 都不读它，留给 FSR2 / DLSS。

### 11. 界面为什么不会因为超分变糊？
- UI 是 Screen Space Overlay 画布，在相机和放大之后、按显示分辨率画（IN-07）。
- 演示时把渲染降到 50%，文字仍然清晰。

## 第三组：中间件与工程设计（12–17）

### 12. `IUpscaler` 接口为什么这么设计？`RecordPass` 为什么是空的？
- 按时间性超分的通用输入设计：颜色、深度、运动向量、遮罩、抖动、MipBias、历史重置。DLSS / FSR2 都能放进来。
- URP 17 自带的三种放大由 URP 自己在后处理末尾记录，我们"拧旋钮"（`renderScale` + `upscalingFilter`）就够了，所以内置后端 `RecordPass` 为空。
- 这是对需求的最小改动，在 DECISIONS 里写明了。尺寸仍然只从 `Initialize` 来，冒烟核对。
- SRP Core 自带的超分框架被 `ENABLE_UPSCALER_FRAMEWORK` 关着（实验性），所以接口放在自己的命名空间。

### 13. 选择器的顺序为什么是 DLSS → MetalFX → STP → FSR1 → 渲染缩放？
- 画质从好到差。厂商原生的 DLSS / MetalFX 有专用硬件和训练好的模型，排最前。
- STP 排在 FSR1 前：STP 是时间性的，能从多帧恢复细节；FSR1 只做单帧。数据也支持：6/6 场景 STP 好。
- 渲染缩放（双线性）兜底，任何机器都能跑。
- 优先级：自动 < 玩家选择 < 启动参数。启动参数指定的不可用时忽略并记原因，不崩溃。

### 14. 能力检测（GpuCaps）和后端的 `IsSupported` 有什么区别？
- GpuCaps 只按硬件、系统、API 判断"可能支持"，每项写明判断依据。比如 DLSS = Windows + RTX + DX/Vulkan。
- `IsSupported` 是后端自己说"我现在真能跑"。比如 STP 查 `STP.IsSupported()`；以后 DLSS 还要查 NVIDIA 的 DLL。
- 两层分开，能力报告可以离线收集、合并分析，不依赖具体 SDK。

### 15. 共享包和游戏代码的边界怎么划？
- 画质分级、能力检测、性能采集三个包来自另一个项目，用 Git 标签引用，不复制代码。
- 项目特有的字段（草、SSAO、反射探针）用包预留的 `TierExtension` 扩展，包不知道"草"是什么。
- 要改包：在包仓库改、升 schema、打新标签，项目再换引用（GpuCaps schema 2 → v0.3.0）。
- 单元测试检查游戏代码不引用厂商 SDK。

### 16. 你怎么防止"编辑器里正常、打包后出错"？
- 冒烟测试跑的是**打出来的包**，不是编辑器。
- 加了一条硬规则：全程不能有任何异常或错误日志。STP 剥离就是这么抓到的类型。
- 会被剥离的资源（STP、GRD）在管线资源里存成开启，运行时再按设置改。
- 诊断用的材质放 `Resources/`，保证进包（GRD 对照组的教训）。

### 17. 如果要把这个中间件给另一个团队用，还缺什么？
- 原生后端（DLSS / FSR2）和它们的 `RecordPass` 实现。
- Halton 抖动接到投影矩阵上（现在只有数学和测试）。
- 跨平台的 CI：现在冒烟只在 Mac 上自动跑。
- 接入规范已有：《超分技术接入规范》，每条有来源编号。

## 第四组：性能与评估（18–23）

### 18. 你怎么评价超分画质？为什么选 FLIP 当主指标？
- 参考图 = 2 倍超采样（4 倍像素）再缩小。
- FLIP 是 NVIDIA 为渲染画质设计的感知指标，模拟人眼在一定观看距离下看出的差异。PSNR 对整体亮度偏移敏感、对锯齿闪烁不敏感；SSIM 看结构。
- FLIP 只看单帧，所以加了"时间稳定性"（静止场景相邻帧亮度差）补闪烁。

### 19. 你怎么知道两个配置的画质差异是真的，不是噪声？
- 噪声底：同一参考配置拍两次，FLIP = 0.0740（M5 Max），这是测试本身控制不住的差异。
- 主要看**逐场景排序**是否一致：STP 质量档在 6/6 场景都比 FSR1、渲染缩放好。
- 测试本身尽量固定：帧步长、随机种子、风相位、每个配置清历史、跑满 60 帧再截图。

### 20. 质量档帧率为什么没到 40%？
- STP +34%、FSR1 +33%、渲染缩放 +42%（M5 Max，2560×1440）。
- 像素只剩约 44%，帧率只提升三成多，说明有不随分辨率变化的开销。报告里推测接近 CPU 瓶颈。
- ❓ 没用 Profiler 拆过 CPU / GPU 时间，这是推测。
- 1070 Ti 更弱，可能更偏 GPU 瓶颈，提升可能更大，但没测前不能说。

### 21. 你怎么测某个特效的开销？
- 一次只关一项，测完马上恢复，开销 = 基线 − 关掉后。4 个机位。
- 关垂直同步，取 GPU 帧时间，去掉最慢 10%。
- Metal 上 GPU 时间含排队，所以只排序不看绝对值；±0.2 ms 以内算测不出。
- 结论：SSAO（1.3–3.8 ms）和草（0.7–1.4 ms）是两大开销（M5 Max，相对值）。

### 22. 讲一个你用数据推翻自己判断的例子。
- GRD：第一轮以为是 Toon 着色器不兼容，后来发现对照方块是粉色错误着色器，根本不走 GRD，对照无效。推翻结论，换成可信对照和最小场景。
- 或者：评估里"质量档比性能档差"，查下去是风相位没对齐。

### 23. 讲一个 GC 优化的例子。
- 发布版看不到每帧分配，改打 Development 包，把 Profiler 数据写文件，在编辑器里按调用路径统计 GC.Alloc。
- 最大来源是 `caught.Exists(c => c.id == id)`：lambda 捕获变量，每次 new 闭包，每只动物每帧一次，约 1.2 KB/帧。
- 还有：隐藏的 `OnGUI` 每帧跑 IMGUI；每帧读 `Transform.name`。
- 结果：10 分钟挂机 GC 512 → 69（M5 Max）。

## 第五组："如果……"（24–29）

### 24. 如果要接入 DLSS，你怎么做？
- 新建 `DlssUpscaler : IUpscaler`：
  - `IsSupported` 查 GpuCaps 的 dlss 字段 + NVIDIA 模块是否加载；
  - `Initialize` 按 DLSS 的档位表返回渲染尺寸；
  - `GetJitter` 用 Halton（已经写好了）；
  - `RecordPass` 在渲染图里声明读颜色、深度、运动向量、遮罩，写输出。
- `UpscalerSelector.Create` 加一行，顺序表不用改，游戏不用改。
- 难点：URP 的抖动要换成我们的；后处理顺序（DLSS 要在色调映射前还是后）。
- 📄 方案见 `docs/设计方案/FSR2-3与DLSS-MetalFX后端.md`，没写代码。

### 25. 如果美术新写了一个带顶点动画的着色器，接到项目里要检查什么？
四件事（写在接入规范里）：
1. 参数放 `UnityPerMaterial`，兼容 SRP Batcher；
2. 有 DOTS 变体，兼容 GRD；
3. 有 MotionVectors Pass，并且用**上一帧的动画参数**算上一帧位置；
4. 如果是透明且没法给运动向量，登记进 Reactive Mask。

### 26. 如果线上玩家反馈"超分开了以后草在拖影"，你怎么查？
1. F3 切到"运动向量"视图，看草有没有颜色。没颜色就是 MV Pass 没跑或被 ForceNoMotion 了。
2. 检查上一帧风时钟 `_WP_WindTimePrev` 是否每帧更新（暂停、读档后是否同步）。
3. 看是否刚发生镜头硬切却没清历史。
4. 用 UpscaleBench 在草地场景跑 STP 和 STP_noMV 对比，量化差多少。

### 27. 如果目标机器是 1070 Ti 这种老卡，你会怎么调默认设置？
- 1070 Ti 没有 RTX，DLSS 不可用；支持 compute，STP 可用。
- 先用测试包的数据看瓶颈：GPU 瓶颈就开 STP 平衡或性能档；CPU 瓶颈超分帮助有限，要减 CPU 开销（GRD、减少物体）。
- 按特效开销清单先关 SSAO、降草距离（低、中档已经这么做）。
- ⏳ 1070 Ti 的测试数据还没回来，以上是方法，不是结论。

### 28. 如果 GRD 在 Windows 上也不工作，你接下来怎么查？
- 编辑器播放模式下试（GRD 校验和日志更多）。
- 用 RenderDoc（Windows）或 Xcode Metal 帧捕获，看 BRG 的绘制命令发没发。
- 检查 Unity 版本的已知问题，最小工程复现后报 bug。
- 和 Unity 官方示例项目对比 URP 资源和图形设置的差异。

### 29. 如果要求帧率提升必须到 40%，你会怎么做？
- 先拆瓶颈：用 Profiler 看 CPU 主线程、渲染线程、GPU 时间。
- 如果 CPU 瓶颈：GRD（批量提交）、减少物体、LOD 更激进；超分本身帮不了。
- 如果是固定开销（阴影、SSAO）：这些在低分辨率下也要跑，可以让 SSAO 跟着渲染分辨率降。
- 或者默认用平衡档：STP 平衡档 FLIP 0.1168，仍在推荐规则内，帧率 173 vs native_stp 120（+44%）。

3. **规则修改要求写明理由**：推荐规则去掉 `native_off` 时，要求在报告里写明"这是改定义错误，不是看了结果再调规则"。
4. **对外文字由我把关**：README 和讲解稿里原来写着"Windows 未验证"。我决定从对外文档里删掉这几个字，Windows 实测结果回来后再补上数据。这本手册和 `docs/简历数据核对.md` 仍然如实写明：目前的数字只来自 Mac。
5. **安全约束**：Tripo 密钥只放在本机配置文件，不进仓库、日志和回复；预算上限 2500 点。
6. **用自动化代替人工检查**：每次提交前必须冒烟 `RESULT PASS`；UI 改动要在 6 种分辨率自动截图。

**面试时怎么说**："代码大部分是 AI 写的，这一点我不回避。我负责定目标、定验收标准、试玩和做取舍，并且要求每个数字能追溯到文件。我能讲清楚每个模块为什么这么设计、数据怎么来的，这本手册就是我学习和核对的过程。"
