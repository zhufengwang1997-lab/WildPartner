## 1. 统一接口 `IUpscaler`

**在哪**：`UP/IUpscaler.cs:18`

```csharp
public interface IUpscaler : IDisposable
{
    string Name { get; }
    bool IsSupported(GpuCapsReport caps);
    Vector2Int Initialize(Vector2Int displaySize, UpscalerQuality quality);  // 返回渲染分辨率
    Vector2 GetJitter(int frameIndex);
    float GetMipBias();
    void RecordPass(RenderGraph graph, in UpscalerInputs inputs, TextureHandle output);
    void ResetHistory();
}
```

**白话**：任何超分算法想接进来，只要会回答这几个问题：
- 你能在这台机器上跑吗？
- 给你这个显示尺寸，你要多大的渲染尺寸？
- 这一帧相机抖多少？
- 贴图要多清晰？
- 你的放大步骤是什么？
- 怎么清空记忆？

`UpscalerInputs`（`:36`）是放大时要的输入：颜色、深度、运动向量、Reactive Mask，全都是渲染分辨率的。

**面试怎么讲**："接口是按 DLSS / FSR2 这类时间性超分的通用输入来定的，所以 STP 这种空间–时间混合的、FSR1 这种纯空间的，都能放进同一个形状。内置后端用不到的方法就返回 0 或留空。"

## 3. 渲染尺寸的唯一来源 `UpscalerHost.Reinit`

**在哪**：`UP/UpscalerHost.cs:55`，窗口变化检测在 `:69`

```csharp
static void Reinit(Vector2Int display)
{
    DisplaySize = display;
    if (!IsUpscaling) { RenderSize = display; return; }
    RenderSize = Active.Initialize(display, Quality);          // the one source of the render size
    (Active as UrpBuiltinUpscaler)?.Configure(Asset());
    Reinitialisations++;
    Debug.Log($"[Upscaling] {Active.Name} {Quality}: display ... -> render ..., mip bias ...");
}

// Hook():
RenderPipelineManager.beginContextRendering += (_, __) =>
{
    if (IsUpscaling && CurrentDisplay() != DisplaySize) Reinit(CurrentDisplay());   // window resized (TC-03)
};
```

**白话**：
- 全项目只有这一个地方决定"这一帧画多大"。别人要用渲染尺寸，都来这里读 `RenderSize`。
- 每一帧开始时比一下窗口尺寸，变了就重算。所以拖窗口、按 F1、改分辨率，都自动走同一条路。

**验证**：
- ✅ 冒烟测试（M5 Max）对每个后端 × 质量/性能档核对：`Screen.width × URP 资源的 renderScale` 和 `RenderSize.x` 相差不超过 1 像素（`Scripts/Core/SmokeTest.cs:706–709`）。
- 注意这里核对的是**写进资源的比例**，不是从 GPU 读回的实际纹理尺寸。

**面试怎么讲**："两个地方各算各的，迟早会差一个像素，导致 UI 对不齐、抖动幅度错。所以定死只有 `Initialize` 能给尺寸。"

## 4. 内置后端：把尺寸写进 URP，按相机设 TAA / MipBias / 历史重置

**在哪**：`UP/Backends/UrpBuiltinUpscaler.cs:47`（Configure）、`:56`（ConfigureCamera）

```csharp
public virtual void Configure(UniversalRenderPipelineAsset asset)
{
    asset.renderScale = RenderScale;          // 渲染宽 / 显示宽
    asset.upscalingFilter = Filter;           // STP / FSR / Linear
    asset.msaaSampleCount = 1;
}

public virtual void ConfigureCamera(Camera cam, UniversalAdditionalCameraData data, bool gameWantsTaa)
{
    cam.allowDynamicResolution = false;
    cam.allowMSAA = false;
    bool taa = Temporal || gameWantsTaa;
    if (taa) data.renderPostProcessing = true;
    data.antialiasing = taa ? AntialiasingMode.TemporalAntiAliasing : ...;

```

**白话**：
- URP 17 自带三种放大（双线性、FSR1、STP），我们不自己写放大 Pass，而是"拧 URP 的旋钮"：渲染比例和放大滤镜。所以 `RecordPass` 是空的。
- `ResetHistory()` 只是记一个标志 `_reset`，下一次相机渲染前才真正设 `resetHistory = true`。原因是 URP 的历史重置是按相机、按帧设置的。

**面试怎么讲**："对需求里'RecordPass 记录放大 Pass'做了最小改动。内置后端放大由 URP 自己在后处理末尾记录。但尺寸仍然只从 `Initialize` 来，冒烟测试核对，所以'唯一尺寸来源'这条没破。"

❓ **待确认**：`taaSettings.mipBias` 在 STP 路径里是否被 URP 使用，没有单独验证过。

## 5. 尺寸、MipBias、Halton 抖动的数学

**在哪**：`UP/UpscalerMath.cs:9`（Scale）、`:17`（RenderSize）、`:24`（MipBias）、`:28`（Halton）、`:36`（PhaseCount）、`:43`（HaltonJitter）

```csharp
Quality => 1f / 1.5f,  Balanced => 1f / 1.7f,  Performance => 0.5f

DefaultMipBias = log2(renderWidth / displayWidth) - 1      // 例：渲染 50% → log2(0.5) − 1 = −2

Halton(index, b): 基数 b 的"倒序小数"，index 从 1 开始
PhaseCount = round(8 × (displayWidth / renderWidth)²)       // 50% → 8×4 = 32 个相位
HaltonJitter(frame, phases) = (Halton(i,2) − 0.5, Halton(i,3) − 0.5)，i = frame % phases + 1
```

**白话**：
- **缩放比例**：质量档每边 1/1.5（像素数约 44%），平衡 1/1.7，性能 1/2（像素数 25%）。
- **MipBias（贴图清晰度偏移）**：画面是小图画的，GPU 会按小图选"更模糊的那一层贴图"（mipmap）。放大后贴图就糊了。负的 MipBias 让 GPU 选更清晰的一层，相当于"按大图的标准挑贴图"。多减 1 是为了补偿时间性累积。
- **Halton 抖动**：每帧把相机挪一点点（不到一个像素），挪的位置按 Halton 序列走，这个序列分布均匀、不扎堆。多帧叠起来，等于在一个像素里采了好多个点。
- **相位数**：放大倍数越大，一个显示像素里要采的点越多，所以和倍数的平方成正比。

**比方**：拍一张很大的风景，相机分辨率不够，就把相机每次往旁边挪"半根头发丝"连拍几十张，再拼起来。Halton 决定每次挪到哪，保证不重复、不扎堆。

**老实说**：🟡 Halton 和相位数公式写了，单元测试 `HaltonSequenceAndPhaseCount` 测过（例：渲染 1280、显示 2560 → 32 个相位），但**运行时没有后端用它**：
- STP 用 URP 自带的 16 相位序列（`StpUpscaler.GetJitter` 返回 `STP.Jit16`，`UrpBuiltinUpscaler.cs:111`）。
- FSR1 和渲染缩放不抖。

它留给以后自己记录 Pass 的原生后端（DLSS / FSR2）。

## 6. 草和树的风：运动向量要用"上一帧的风"

**在哪**：`Shaders/ToonCommon.hlsl:39–41`（全局参数）、`Shaders/Toon.shader:337`（MotionVectors Pass）、约 `:381`（vert）

```hlsl
float  _WP_WindTime;      // time used this frame
float  _WP_WindTimePrev;  // time used last frame (for motion vectors, IN-03)

// Toon.shader MotionVectors vert:
float3 cur  = ApplyWindOS(v.positionOS.xyz, v.color.r, _WP_WindTime);
float3 prevBase = (unity_MotionVectorsParams.x == 1) ? v.positionOld : v.positionOS.xyz;
float3 prev = ApplyWindOSPrev(prevBase, v.color.r, _WP_WindTimePrev);
o.curCS  = mul(_NonJitteredViewProjMatrix, mul(UNITY_MATRIX_M,      float4(cur, 1)));
o.prevCS = mul(_PrevViewProjMatrix,        mul(UNITY_PREV_MATRIX_M, float4(prev, 1)));
// frag: return float4(CalcNdcMotionVectorFromCsPositions(i.curCS, i.prevCS), 0, 0);
```

**白话**：一个像素的运动 = "这一帧在屏幕哪" − "上一帧在屏幕哪"。上一帧的位置要把三件事都倒回去：
1. **相机**：`_PrevViewProjMatrix`，上一帧的相机。
2. **物体**：`UNITY_PREV_MATRIX_M`，上一帧的物体位置和朝向。
3. **顶点自己动的部分**：
   - 风：用上一帧的风时钟 `_WP_WindTimePrev` 重算一次；
   - 蒙皮动画：`unity_MotionVectorsParams.x == 1` 时，Unity 提供了 `positionOld`，就是上一帧蒙皮后的顶点。

**注意**：当前帧用 `_NonJitteredViewProjMatrix`（不带抖动的矩阵），运动向量里不能混进抖动，否则静止的画面也会"在动"。

**顶点色 R** 是风的权重：树干根部 0，叶尖 1。资源处理脚本画进去的。

**面试怎么讲**："顶点动画最容易漏运动向量。物体没动，Unity 就认为运动是 0，超分就会在摆动的树叶上拖影。我们把上一帧风时钟也传进来，在 MV Pass 里重放一遍上一帧的风。"

## 7. GPU 实例化草：一次调用画一整块

**在哪**：`Scripts/World/GrassRenderer.cs:195`（RenderParams）、`:201`（运动向量模式）、`:225`（提交）

```csharp
var rp = new RenderParams(material)

    shadowCastingMode = ShadowCastingMode.Off,
    receiveShadows = true,
    motionVectorMode = MotionVectorGenerationMode.Object,   // 让它进 MotionVectors Pass
```

**草叶形状在着色器里算**：`Shaders/Grass.shader` 的 `BuildBlade(v, time)`，用实例编号算出格子、格子哈希、地形高度、风。MotionVectors Pass（`:268`）调用两次 `BuildBlade`：一次用当前风时钟、一次用上一帧的（`:281`），再乘上一帧的视图投影矩阵 `_PrevViewProjMatrix`（`:284`）。

- 每丛草长什么样、在哪，GPU 自己按格子编号算出来。
- 远处的块用更简单的网格。草叶在着色器里按距离逐渐缩到零，换网格时看不出跳变。

**面试怎么讲**："草是天然的 GPU 实例化场景：数量大、形状可以程序化生成。所以不需要 GRD。开销实测 0.7–1.4 ms（M5 Max，相对值），是第二大开销。"

## 8. Reactive Mask：给"没有运动向量的透明物"做标记

**在哪**：`Scripts/Rendering/ReactiveMaskSources.cs:15–25`、`Scripts/Rendering/UpscalerInputsPass.cs:39`（Pass 时机）、`:54`（MaskPass）、`:71`（按渲染层过滤）

```csharp

{
    r.motionVectorGenerationMode = MotionVectorGenerationMode.ForceNoMotion;
```

## 11. Toon 着色器：一个着色器五个 Pass，兼容 SRP Batcher 和 DOTS

**在哪**：`Shaders/Toon.shader`：ForwardLit `:41`、ShadowCaster `:183`、DepthOnly `:242`、DepthNormals `:288`、MotionVectors `:337`；`Shaders/ToonCommon.hlsl:11–29`（CBUFFER）、`:31–35`（DOTS）

```hlsl
// ToonCommon.hlsl
CBUFFER_START(UnityPerMaterial)
    float4 _BaseMap_ST; half4 _BaseColor; half4 _ShadowColor; half4 _RimColor; ...
    half _RampSteps; half _RampSmooth; half _WindStrength; half4 _EmissionTint; ...   // 共 17 个材质参数
CBUFFER_END

#if defined(UNITY_DOTS_INSTANCING_ENABLED)
UNITY_DOTS_INSTANCING_START(MaterialPropertyMetadata)
    UNITY_DOTS_INSTANCED_PROP(float4, _BaseColor)
UNITY_DOTS_INSTANCING_END(MaterialPropertyMetadata)
#endif

// 每个 Pass：#include_with_pragmas ".../DOTS.hlsl"
// ForwardLit:131
half3 n = SafeNormalize(i.normalWS) * (facing ? 1 : -1);   // 1123e-1: 零法线不能变成 NaN
```

（CBUFFER 只列了部分字段，完整的 17 个见文件 `:11–29`。）

**白话**：
- **SRP Batcher** 的要求：所有 Pass 的材质参数放在同一个常量缓冲区（`UnityPerMaterial`）里，布局一样。这样 GPU 可以把参数一次性留在显存里，换物体时不用重新上传，切换成本很低。
- **DOTS Instancing**：GRD 用 BatchRendererGroup 画，参数从一个大缓冲区按实例读。要声明哪些属性是"每个实例不一样"的，这里是 `_BaseColor`。
- **ForwardLit** 的卡通光照：N·L 量化成几档（`:111–115`），档与档之间用 `smoothstep` 软一点；阴影往蓝紫偏，加边缘光。

**面试怎么讲**："写一个自定义着色器，平台组要检查四件事：SRP Batcher、DOTS 变体、运动向量、阴影和深度 Pass 是否齐全。我在 Toon 着色器上都做了，在《超分技术接入规范》里写成了检查表。"

## 16. 画质指标：FLIP / SSIM / PSNR

**在哪**：`Packages/com.zfw.upscaling/Tools~/quality_eval.py:26`（psnr）、`:31`（ssim）、`:36`（flip）、`:49`（evaluate）；`Tools~/bench_report.py:66`（推荐规则）、`:83`（NFR-01）

```python
    natives = [v["flip"] for k, v in summary.items() if k.startswith("native_") and k != "native_off" ...]

```

**三个指标，白话版**：

| 指标 | 量什么 | 比方 | 方向 |
|---|---|---|---|
| **FLIP**（NVIDIA，主指标） | 模拟人眼在一定观看距离（67 像素/度）下"翻来覆去对比两张图"时能看出的差异 | 找不同游戏，按人眼能看出来的程度打分 | 越小越好 |
| **SSIM** | 结构相似度：亮度、对比度、纹理结构像不像 | 两张照片"轮廓和纹理"像不像 | 越接近 1 越好 |
| **PSNR** | 逐像素误差换算成分贝 | 逐个像素对账，算平均差多少 | 越大越好 |

还有**时间稳定性**：静止场景连拍 60 帧，相邻帧亮度差的平均值，越大越闪。

**面试怎么讲**："PSNR 对亮度整体偏移很敏感，对人眼在意的锯齿、闪烁不敏感；FLIP 是为渲染画质设计的感知指标，所以拿它当主指标，SSIM、PSNR 作参考。另外 FLIP 只看单帧，闪烁要靠时间稳定性一列补上。"

## 18. GC：从 Profiler 数据找到分配来源

**在哪**：
- `Assets/_Game/Editor/ProfileAllocReport.cs:20`（Run）、`:33`（读 Profiler 帧）、`:43`（找 GC.Alloc）。
- 修复：`Scripts/Core/SaveSystem.cs:37`（HasCaught）、`Scripts/Rendering/DebugOverlay.cs:140`（DebugOverlayGUI）。

```csharp
// ProfileAllocReport：遍历每一帧的调用树，遇到 "GC.Alloc" 就把字节数记到它的调用路径上
using var v = ProfilerDriver.GetHierarchyFrameDataView(f, 0, ..., HierarchyFrameDataView.columnGcMemory, false);
if (n == "GC.Alloc") { 记 path、字节数、次数 }

// 修复前：caught.Exists(c => c.id == id)   —— 每次调用都新建一个闭包对象
// 修复后：
public bool HasCaught(string id)
{
    for (int i = 0; i < caught.Count; i++) if (caught[i].id == id) return true;
    return false;
}

// F3 面板：OnGUI 挪到单独组件，只在面板显示时启用
public class DebugOverlayGUI : MonoBehaviour { void OnGUI() { if (owner) owner.DrawGUI(); } }
```

**白话**：
- **GC（垃圾回收）**：C# 里 `new` 出来的东西用完了，要由运行时定期打扫。打扫时游戏会顿一下。每帧都 new 一点，打扫就频繁。
- **lambda 带捕获**：`c => c.id == id` 用到了外面的 `id`，C# 会偷偷 new 一个小对象来装 `id`。每只动物每帧调一次，积少成多，约 1.2 KB/帧。
- **OnGUI**：只要有一个启用的组件写了 `OnGUI`，Unity 每帧都跑一遍 IMGUI，即使什么都不画也分配内存。

**结果**：✅ 10 分钟挂机（M5 Max）GC 次数 512 → 69；每帧分配 2582 B → 506 B（含退出过程，扣掉后稳态约 135 B）。数据：`bench_results/soak-mac-20261123*/`、`bench_results/allocprof-mac-20261123/before.txt`、`after.txt`。
