## 三、唯一需要用户动手的事：Tripo 密钥（开工第一件事就发起，不要等它）
1. 建空文件 `~/.config/tripo/api_key`（仅本人可读写），用"文本编辑"替用户打开，告诉用户：把密钥粘进去 → Command+S 保存 → 关窗口。密钥从 platform.tripo3d.ai 的 API Keys 页面获取，以 tsk_ 开头。
2. 密钥只从这个文件读。绝不能出现在项目文件夹、Git、日志或你的回复里。
3. 可以用 github.com/SucRunBug/tripo-3d 这个 skill（`python3 scripts/install.py --target claude`），用前通读其脚本确认无可疑行为；有疑虑就按 Tripo 官方 API 文档自己写调用脚本。
4. 配好后先用不花钱的接口验证连通并查余额，把余额告诉用户。
5. **只用 Tripo 生成模型，不用它的骨骼绑定和动画功能。**

用户还没录入密钥时，先做第四节里不依赖模型的部分。

## 四、工作顺序

### A. 立即做（不依赖新模型）
1. 提交当前未提交的改动（你已经开始写的 `rig_humanoid.py` 等）。
2. **光照、雾、后处理**（PRD-补充 第 3 节）：这是画面最大的问题，先解决。
3. **按 600 m 完整地图重做布局**（PRD-补充 第 1、2 节），物件全部先用占位体，把各区域位置、小路走向、重点区构图定下来。修掉河流汇入处的方形水面接缝。
4. **女巫小屋**（玩法设计"女巫小屋"一节）：室内用用户已做好的 7 件家具 + 你用 Blender 搭的梁柱地板墙面；玩家在床上出生；门口按 E 淡入淡出进出；床可睡觉（存档 + 切换昼夜）；桌上的书是图鉴。
5. **玩法改造**（玩法设计全文）：猫作为默认宠物及其三种闲置行为；兔的高跳；鹿的"走三秒低头吃草"和骑乘；锦鲤的踏水；蝴蝶在湖心岛月光花上、被收集后环绕飞行带紫色尾焰；情境化的 E 键提示；新结局。**模型和骨骼没到位的先用占位体和程序化动画把逻辑做通**，保证任何时候游戏都能从头玩到尾。
6. 用户的猫模型已做好但还不在 `_Inbox` 里：提醒用户放进去（或问清楚文件在哪，自己拷过来）。

### B. Tripo 模型生成（密钥到位后启动，与 A、C 并行，生成是异步的，提交后去干别的，定期回来取）
1. 不重复生成用户已有的：主角女巫、月影兔、月影蝶、白色神鹿、猫、室内 7 件家具。
2. 提示词用清单里的，末尾都加统一风格句。
3. **木屋外观、围栏、路灯、旗帜、炼药锅、种植箱、储物箱**：优先用"图片转 3D"，从 `docs/reference/女巫木屋拆解.png` 的"关键元素与材质参考"区域裁出对应物件的图作为输入，这样最接近用户的参考图。
4. 第一个先做 Tree_Broadleaf：下载后渲染预览图，和 `docs/reference/style.jpg` 并排自查，并记下实际扣了多少点数，汇报给用户，**然后不等回复继续**。
5. 顺序：A 级 → C 级（小屋院子）→ B 级。
6. 每个模型渲染预览自查：风格与已通过的一致、单个完整物体、无破面、无多余底座。不合格重做，同一个最多重做 2 次，仍不行就先用着并在汇报里标出。
7. 任务编号和状态记到 `tools/tripo/jobs.json`，中断后从记录恢复，**绝不重复提交已成功的任务**。
8. **预算上限 2500 点**。到上限就停止生成、告诉用户，其余工作照常继续。
9. 每到一个模型：按 PRD-补充 第 4 节处理（减面、保留贴图、LOD、统一原点尺寸）→ 替换占位体 → 该区域截图存档。
