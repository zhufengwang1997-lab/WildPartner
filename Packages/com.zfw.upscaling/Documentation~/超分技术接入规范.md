# 超分技术接入规范（com.zfw.upscaling）

本规范写给"要在自己的 Unity URP 项目里接入 `com.zfw.upscaling`"的人，也写给"要给它加一个新后端"的人。内容以本仓库实际代码为准；没做的部分明确标出。

## 1. 结构
```
游戏层（WildPartner.Runtime）
  └─ UpscalerSettings：读存档/档位/启动参数 → UpscalerSelector.Select → UpscalerHost.Use
中间件（Zfw.Upscaling，不引用任何厂商 SDK）
  ├─ IUpscaler / UpscalerQuality / UpscalerInputs   接口（说明书 FR-UP-01）
  ├─ UpscalerSelector                                 选择器（FR-UP-04）
  ├─ UpscalerHost                                     运行时：初始化、分辨率变化、相机配置、历史重置
  ├─ UpscalerMath                                     缩放比例、Mip 偏移、Halton(2,3) 抖动与相位数
  └─ Backends/UrpBuiltinUpscaler.cs                   RenderScale / FSR1 / STP 三个后端
```
游戏层只调用 `UpscalerSelector`、`UpscalerHost` 和 `IUpscaler` 的公开成员，**不认识任何具体后端的内部**。加一个后端不需要改游戏层代码（NFR-05；STP 后端就是这样加进来的）。

## 2. 后端现状
| 后端 | 实现方式 | 平台 | 状态 |
|---|---|---|---|
| RenderScale | URP 渲染比例 + 双线性放大 | 全部 | Mac 已验证 |
| FSR1 | URP 内置 FSR 1（EASU + RCAS），说明书允许的回退路径；FSR 2/3 原生插件未做 | 全部 | Mac 已验证 |
| STP | URP 内置 STP（时间性），需要计算着色器 | Metal / DX12 / Vulkan | Mac 已验证 |
| MetalFX | 原生插件 `MTLFXTemporalScaler` | macOS | 仅设计 |
| DLSS | `UnityEngine.NVIDIA` 模块，URP 17 无内置 | Windows + RTX | 仅设计 |

选择顺序：DLSS → MetalFX → STP → FSR1 → RenderScale，取第一个 `IsSupported` 为真的。DLSS 和 MetalFX 没有实现，不在注册表里。STP 排在 FSR1 前，因为它是时间性的，能从多帧里恢复细节；FSR1 只对单帧做放大和锐化。

## 3. 接口的四条规则
1. `Initialize(display, quality)` 返回的渲染分辨率是唯一来源。内置后端把它换算成 URP 的 `renderScale` 写进管线资源，冒烟测试会核对 URP 实际渲染宽度与返回值是否一致。
2. 显示分辨率或档位变化 → 重新 `Initialize` 并重置历史。`UpscalerHost` 每帧开始前比较窗口尺寸；游戏在换档位时调用 `UpscalerHost.Reapply()`。
3. `RecordPass` 只声明渲染图资源。**偏离说明**：三个内置后端的放大 Pass 由 URP 自己在后处理末尾记录，所以它们的 `RecordPass` 是空的。原生后端（FSR2/3、DLSS、MetalFX）才在这里声明输入输出。
4. `GetMipBias()` = log2(渲染宽 / 显示宽) − 1。内置后端写进相机的 `taaSettings.mipBias`，URP 与它自己按渲染比例算出的偏移取较小值，然后作为全局 `_GlobalMipBias` 生效（URP 的 `SAMPLE_TEXTURE2D` 宏会带上它）。

## 4. 输入准备清单（IN-01 ~ IN-08）
| 编号 | 要求 | 本项目做法 | 状态 |
|---|---|---|---|
| IN-01 | 按渲染分辨率渲染，关掉重复的抗锯齿 | STP：URP 用 STP 取代 TAA，不会叠加。FSR1 / 双线性是空间放大，保留游戏的 TAA 开关（关掉会满屏锯齿） | 已实现；渲染尺寸由冒烟测试核对 |
| IN-02 | 深度与 Reversed-Z | 用 URP 深度纹理；URP 按平台处理方向。F3 面板显示当前平台是否 Reversed-Z | 已实现（Mac 为 Reversed-Z） |
| IN-03 | 运动向量（蒙皮、植被风动） | 时间性模式下 URP 跑 Motion Vector Pass。Toon、草、蒙皮网格都写运动向量。F3 → 运动向量视图 | 已实现，视图截图见冒烟 `7y_view_motion_vectors` |
| IN-04 | Halton(2,3) 抖动，相位数 8×(显示/渲染)² | 公式在 `UpscalerMath`，有单元测试。**内置 STP 用的是自己的 16 相位序列 `STP.Jit16`**，后端 `GetJitter` 返回它 | 公式已实现并测试；当前后端未使用 Halton |
| IN-05 | 曝光 | 游戏没有自动曝光（固定曝光 + 调色），内置后端不读曝光 | 不适用；原生后端接入时传 1×1 曝光纹理 |
| IN-06 | Reactive Mask | 雨、瀑布水雾、蝴蝶星尘等无运动向量的粒子注册到 `ReactiveMaskSources`：关运动向量、打渲染层标记。每帧画进 R8 遮罩 `_WP_ReactiveMask`。F3 → Reactive Mask 视图 | 已生成；**当前后端未消费** |
| IN-07 | UI 在超分之后按全分辨率绘制 | UI 是 Screen Space Overlay 画布和 IMGUI，不经过相机，天然在放大之后 | 已实现；超分截图中文字保持锐利 |
| IN-08 | 镜头切换、传送、分辨率或档位变化时重置历史 | 进出木屋和传送触发 `PlayerController.CameraCut` → `AntiAliasing.ResetHistory()` → `UpscalerHost.ResetHistory()` → 下一帧相机 `resetHistory = true` | 已接入；鬼影对比截图未做 |

## 5. 新增一个后端
1. 新建类实现 `IUpscaler`（URP 内置能力就继承 `UrpBuiltinUpscaler`）。
2. 在 `UpscalerSelector.Create` 和 `Order` 里注册名字。
3. 在 `Tests/Editor` 里加选择器用例。
4. 游戏层不改代码。设置菜单的方案列表来自 `UpscalerSelector.Available`，会自动出现新后端。

原生后端（FSR 2/3、DLSS、MetalFX）的建议路线：打开 URP 的 `ENABLE_UPSCALER_FRAMEWORK`，把后端同时包成 SRP 的 `AbstractUpscaler`，由 URP 在正确的位置调用 `RecordRenderGraph`。输入从 `UpscalerInputs` 取（颜色、深度、运动向量、Reactive Mask、抖动、重置标志）。

## 6. 常见问题排查
- **切到 STP 后黑屏，日志每帧出现 `STP.Execute` 空引用**：打包时 STP 资源被剥离了。只要有一份管线资源的放大滤镜存成 STP，打包就会保留资源（本项目四档都存成 STP）。
- **所有模式帧时间一样（8.3 ms 或 16.7 ms）**：测到的是垂直同步间隔。测量时关垂直同步，用 FrameTimingManager 的 GPU 时间（`GpuTimer`）。
- **后来创建的相机没有抗锯齿**：场景相机比设置加载得晚。在 `beginCameraRendering` 里逐相机检查设置。
- **远处贴图变糊或闪烁**：检查 Mip 偏移有没有生效（F3 面板显示当前值）。
- **快速转镜头时出现拖影**：检查运动向量视图里该物体有没有颜色；没有颜色的透明物体要么写运动向量，要么注册到 Reactive Mask。
